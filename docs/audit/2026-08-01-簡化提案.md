# 專案頁簡化提案與實作說明（2026-08-01）

依據：`2026-08-01-專案頁體檢報告.md` 的實測證據。

## 一、為什麼要簡化

專案頁一頁裝了 3 大章、20+ 區塊、80+ 可互動元素。但實測「從零到第一支可交付的片」真正必要的只有四個動作：

**講一句故事 → 拆分鏡 → 逐格出圖 → 送審打包**

其餘（協作視角、訊息主軸、視覺風格三層選擇、進階敘事欄位、四個創作模式分頁、資料表六種範本…）對第一次用的人都是路障。而且最好用的路徑其實已經存在——免費「一起想」助手會讀全部上下文、拆好分鏡、附一鍵接手按鈕。簡化版就是把它扶正成主線。

## 二、欄位處置

### 簡易模式不出現
| 項目 | 理由 |
|---|---|
| 頂部「你想完成什麼畫面？」鏡射框＋「請誰來幫忙」 | 無送出行為、與分頁輸入框重複（使用者實測回報「上面的無法使用」） |
| 協作視角切換（一般／鏡像跟隨） | 進階協作，首次產出用不到 |
| 訊息主軸、視覺風格三層（媒材／主風格／質感／自訂） | 主軸只進文字 AI；簡易版收斂成一列「調性」 |
| 參考連結 | 程式碼證實不進任何模型，只進匯出備註 |
| 資料表六種範本、成員權限、回收桶、素材庫多選 | 都收在完整版 |

### 合併
- 四個創作模式分頁 → 一條線的四步，每步一個輸入框配一顆主按鈕
- 專案知識庫＋專案資料 → 完整版仍分開；簡易版直接讀知識庫既有腳本自動預填
- 頂欄剩／週／日三個數字 → 建議收成一顆點數鈕（含逐筆明細）＝**待辦，需先修 P1-1**

### 誠實化（皆經程式碼對抗驗證）
- 「AI 全程共用」chips 只列真正注入的欄位；素材改標「AI 只看得到清單，不讀內容」
- 禁忌事項在不支援負向提示的模型（含預設 FLUX.1 dev）顯示「此模型不支援」
- 定裝參考圖標示「僅供人工比對，不送入模型」＝**待辦（完整版文案）**

## 三、新手最短路徑（實作為 4 步，其中 3 步需要動手）

1. 建專案（名稱＋類型）
2. 一句話故事 ＋ 點一個調性
3. 貼腳本 → 按「AI 幫我拆成分鏡（免費）」→ 一次建立全部格子
4. 按「生成剩下 N 格」→ 背景逐格出圖 → 「送審 N 格」＋「打包下載」

## 四、長時間任務的處理

- 進度四步**全部由伺服器資料推導**（世界觀、分鏡列、審核狀態）→ 重整／關頁／換裝置回來看到同一個進度
- 生成中顯示常駐條「N 格畫面生成中——可以關掉這頁，完成會推播通知」
- 分鏡查詢在有格子生成中時每 3 秒輪詢，且 `refetchIntervalInBackground`（切分頁也繼續）
- 一鍵生成逐格送出、跳過已在生成中的格子（避免重複扣點與互相覆蓋）
