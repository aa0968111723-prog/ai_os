## 一、總結

核心設計是對的：**上下文注入鏈真實有效**、長任務機制（背景執行／可關頁／推播／失敗退點）完整、交付包規格專業。但四個問題讓它在真實使用中站不住：

| 級別 | 問題 | 一句話 |
|---|---|---|
| P0 | 素材非持久 | 花點數生成的影片與配音，20 分鐘後（伺服器重啟）就 404 消失 |
| P0 | 製作範本全滅 | 所有含文字步驟的範本都因 NVIDIA NIM 404 失敗 |
| P1 | 點數顯示不可信 | 同一支影片四處四個數字；頂欄「剩」根本不隨消費變動 |
| P1 | 代理規劃器過嚴 | 一般人寫的目標連續失敗，要寫成工程規格才通過 |

點數消耗：全程 **19 點**（預算 200）。多數失敗動作都有自動退點，這點做得好。

## 二、P0 問題

### P0-1 素材非持久（付費產物會蒸發）
**重現**：
1. 06:07 用 Wan 2.2 生成影片（扣點成功，1.86MB，可播放）
2. 06:26 用 TTS 生成旁白音檔（成功）
3. 06:40 前後站台出現一次 502（伺服器重啟）
4. 重整後 `HEAD /api/assets/<id>/file`：影片 **404**、音檔 **404**；同期兩張圖片仍 200

**證據**：素材卡片自己顯示「音檔遺失（可能是伺服器重啟前的舊檔）」——程式已經知道會發生這件事。

**影響**：使用者花的每一點都可能白花；分鏡預覽破圖、交付包缺媒體。

**修法**：Zeabur 掛持久 Volume 到 `/data` 並設 `ASSET_DIR`，或改存物件儲存（S3/R2/Supabase Storage）。這是部署設定，程式面（遺失回乾淨 404、系統自檢偵測非持久儲存）已在 2026-07-25 PR #104 做完。

### P0-2 製作範本整條不可用（NIM 404）
**重現**：AI 創作中心 → 套用範本 → 選「旗艦・金句卡」→ 填一句話 → 執行
**實際**：步驟「摘金句」失敗，錯誤 `NVIDIA NIM API 錯誤 (404): 404 page not found`（模型 Qwen2.5 72B）。改用「經濟・金句卡」同樣失敗。
**推論範圍**：所有含 LLM 文字步驟的範本（7 個裡至少 6 個）；「回答模型＝只用 NIM」也必死；多步開拍規劃走 NIM 檔位同樣風險。
**倖存原因**：「一起想」助手預設走 fal（Claude Sonnet 4.5），所以沒被影響。
**修法**：校正 NIM base URL／model id，並在 NIM 失敗時自動 fallback 到 fal LLM（現在只有規劃器有 fallback，範本沒有）；系統自檢加一條 NIM 健康檢查。

## 三、P1 問題

### P1-1 點數顯示四處不一致
同一支 Wan 2.2 影片：

| 位置 | 數字 |
|---|---|
| 模型下拉選單 | 1 點 |
| 「即將生成」確認卡 | 約 12 點 |
| 生成紀錄卡片 | −1 點 |
| 實際扣款（quota API `totalUsed` 60→62） | 2 點 |

**頂欄「剩 1,133」不會隨消費減少**——它顯示的是 `falPointsCap`，不是 `totalBudget − totalUsed`（5000−62=4938）。跨日時還閃現過「剩 4,940」（另一條公式），兩種定義互打。
**修法**：全站統一一個「剩餘」定義；預估與實扣用同一份計價函式；使用者選單加逐筆明細（現在只有 剩／今日／本週 三個數字，對不了帳）。

### P1-2 代理規劃器對一般人的寫法必死
「幫我執行生成分鏡表」「為第3鏡生成畫面並配旁白」→ 連續兩次「AI 兩次都沒有產生符合安全規格的完整計畫，請把目標、日期或交付成果說得更具體」。要寫成「兩步計畫，今天完成：步驟1用文生圖生成「…」加入分鏡；步驟2用文字轉語音生成…。交付成果：1張分鏡圖與1段旁白音檔」才通過。
**修法**：失敗時改成引導式追問（缺什麼問什麼），或提供三個可點的範例目標。

### P1-3 代理執行靜默漏做
計畫寫明「加入分鏡」，執行完顯示「已完成・成果 2」，但分鏡沒有新增（圖只進了素材庫）。使用者只看狀態標籤會以為做完了。

### P1-4 打包完成但 UI 永遠卡在「排隊中」
`exportJobs` 伺服器端 2 秒就 `done`（實查 API 確認），前端進度條不更新、不出現下載鈕；重整後連「上次打包」都找不到，只能重打一次。
**根因**：React Query 在背景分頁停掉輪詢；jobId 只存 React state。
**已修**（本次 PR）：jobId 存 localStorage ＋ `refetchIntervalInBackground: true`。

### P1-5 連按「存成分鏡草稿」只有最後一顆生效
AI 拆出 4 鏡、附 4 顆「存成分鏡草稿」按鈕。每顆按下後還要再按一次「執行」確認；連續點 4 顆時，新的確認靜默取代前一個，最後只存進 1 鏡，沒有任何提示。

### P1-6 儀表板底部「建立新專案」看起來壞掉
按下去後表單開在頁面頂端 hero 區，不自動捲動、原地毫無回饋（頂部按鈕文字變成「收起建立表單」但在視窗外）。

### P1-7 AI 創作中心雙輸入框（使用者回報，已重現）
頂部「你想完成什麼畫面？」會鏡射到分頁的目標欄，但自己沒有送出行為 → 使用者以為壞掉。

### P1-8 影片與圖片同價（商業風險）
Sora 2／Veo 3.1／Kling 3.0 全部標 1 點，和一張 FLUX 圖同價；週額度 300 點理論上可燒 300 支影片，平台實付 USD 會爆。另有反向錯亂：`ffmpeg-api/merge-videos` 標 22 點、`fal-ai/fast-sdxl` 標 22 點，比旗艦影片還貴。

## 四、P2 問題

- 分鏡「生成這一格」固定用 SDXL Lightning，不可選模型；中文字卡與寫實人物遵從度差（提示詞是「灰帽T男子在公園長椅」，產出紅傘藍衣古裝人物）。
- 範本失敗後目標欄被清空，按鈕變 disabled 且不說明原因。
- 「配音」步驟沒做卻在流程列打勾。
- 章節導覽點擊有時只改 hash 不捲動。
- 世界觀文字欄靠 blur 存檔，成功提示一閃即逝。
- 全組共用的自訂選項會累積垃圾（實見風格選項「安安」）。
- 頁面捲動時常整頁空白閃爍。
- 快速短語遇到 502 時，把原始 JSON parse 錯誤直接顯示給使用者。
- 線上站本輪至少 2 次 502。

## 六、值得保留並強化的優點

1. **上下文注入鏈透明**：生成紀錄可展開「完整注入提示詞」；知識庫有「預覽 AI 會讀什麼」（顯示納入字數／是否截斷／字數預算）。這是同類產品少見的誠實。
2. **免費「一起想」助手品質高**：正確引用知識庫＋角色＋場景，產出 4 鏡分鏡，並附「存成分鏡草稿／帶入直接出圖／建立多步開拍」一鍵接手。
3. **長任務體驗**（生成部分）：背景執行、可關頁、重整恢復、完成推播、失敗自動退點＋「以相同設定重試」。
4. **生成前確認卡資訊完整**：模型／規格／注入摘要／預估點數／目前剩餘／是否需核准。
5. **四步精靈自動打勾**＋「AI 全程共用」計數即時更新。
6. **交付包規格專業**：fcpxml／Premiere xml／srt／edl／鏡頭表＋剪映 CapCut 單檔＋粗剪預覽播放器（含自動換鏡、同步播旁白）。
7. **回收桶**（刪除可還原、不扣點）、**成員權限**（唯讀檢視者）、**合規禁語預設三條**。
8. **留言區系統稽核訊息**自動入流（送審／通過），並可轉待辦／轉筆記／釘選。
