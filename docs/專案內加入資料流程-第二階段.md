# 專案內加入資料流程：第二階段

> 對應第一階段：PR #127「統一專案、資料來源與 AI 使用介面」
>
> 本階段目標：把「知道名稱」推進到「在專案裡知道從哪裡開始」，建立專案資料入口與明確的 AI 可讀判斷。

## 一、研究結論

目前系統其實已具備多種資料能力：

- 專案知識庫：貼上文字、批次匯入 txt／md。
- 素材庫：圖片、影片、音訊與生成成品。
- 自訂資料表：CSV、TSV、JSON、文件與結構化資料。
- 外部來源：Google Drive、Notion、外部 API。
- 專案關聯資料：資料表使用「專案連結」欄位指向專案。
- AI 創作助手：可讀取專案知識與允許使用的資料。

問題不在缺少功能，而在功能分散：

1. 專案頁的知識庫、資料表與素材庫是不同卡片。
2. 沒有關聯資料時，原本的資料表卡整張不顯示。
3. Google、Notion、API 位於帳號層級的整合頁。
4. 使用者容易把「已連接帳號」誤認為「AI 已讀取內容」。
5. 結構化資料必須有專案連結欄位才會在專案中彙整，但這項規則不容易被發現。

## 二、本 PR 的產品調整

### 2.1 專案內固定顯示資料入口

`ProjectDatabasesCard` 從「有資料才顯示的唯讀彙整」調整為固定入口：

```text
加入資料與專案資料表
├── 貼上文字／上傳 txt、md
├── 上傳圖片、影片、音訊
├── Google／Notion／API
└── CSV、JSON 與資料表
```

使用者不需要先知道資料應該屬於知識庫、素材庫、資料表或整合頁。

### 2.2 保留既有能力與路由

本階段不建立新的後端匯入模型，而是將使用者帶到既有安全入口：

- 文字資料 → 專案知識庫 `#sec-knowledge`
- 媒體資料 → 專案素材庫 `#sec-assets`
- 外部來源 → `/integrations`
- 結構化資料 → `/databases?projectId=<id>&from=project`

這樣可以先降低操作成本，同時避免複製上傳、解析、權限與加密邏輯。

### 2.3 明確定義 AI 可讀狀態

介面使用以下規則說明：

- 文字出現在專案知識庫：AI 可在目前專案引用。
- 資料列出現在「已連到本專案的資料」：AI 可依資料表的 AI 權限使用。
- 只有 Google／Notion／API 顯示已連接：尚未代表 AI 已讀取內容。
- 媒體出現在素材庫：可作為生成來源；是否能理解內容仍依模型與解析能力而定。

## 三、使用者流程

### 3.1 文字文件

```text
進入專案
→ 加入資料與專案資料表
→ 貼上文字／上傳 txt、md
→ 加入專案知識庫
→ AI 創作助手可引用
```

### 3.2 Google／Notion／API

```text
進入專案
→ 加入資料與專案資料表
→ Google／Notion／API
→ 完成個人來源連接
→ 前往知識與資料匯入指定內容
→ 將內容加入或連回專案
→ AI 創作助手可引用
```

### 3.3 CSV／JSON／資料表

```text
進入專案
→ 加入資料與專案資料表
→ CSV、JSON 與資料表
→ 建立或匯入資料表
→ 新增「專案連結」欄位
→ 選擇目前專案
→ 回到專案查看關聯資料
```

## 四、安全與相容性

本階段不修改：

- tRPC procedure 名稱。
- 資料庫 schema。
- Google、Notion、API 憑證加密方式。
- `databaseAcl` 與 AI 存取權限。
- MCP 工具契約。
- 點數、核准、審計與背景執行。
- 原有 `/integrations`、`/databases` 路由。

所有入口仍受既有後端權限守門，前端導引不會擴大資料可見範圍。

## 五、驗收條件

- [ ] 專案沒有任何關聯資料時，仍看得到加入資料入口。
- [ ] 可以從專案一鍵捲到知識庫與素材庫。
- [ ] 可以從專案前往 Google／Notion／API 連接頁。
- [ ] 可以帶著目前 `projectId` 前往資料表頁。
- [ ] 已連結資料表仍能在專案內預覽。
- [ ] 介面清楚說明「連接來源不等於 AI 已讀取」。
- [ ] 載入失敗時顯示錯誤，不把失敗誤顯示成空資料。
- [ ] 原有資料列預覽、資料表深連結與 ACL 行為維持不變。

## 六、後續第三階段

第二階段先建立入口；下一階段再做完整閉環：

1. `/integrations` 保留 `projectId`，授權後回到原專案。
2. `/databases` 顯示「來自哪個專案」並提供返回專案。
3. Google Drive 與 Notion 增加瀏覽／選取器，不再只靠貼網址。
4. 匯入完成後自動建立專案關聯。
5. 文件解析顯示 `上傳中／解析中／AI 可讀／失敗／需要 OCR`。
6. AI 產生摘要、缺漏、風險與證據引用。
7. 分析結果可轉成任務、專案摘要、資料表、分鏡或 AI 執行計畫。

## 七、完成定義

本階段完成後，使用者在專案內不必先理解「知識庫、資料庫、整合、素材庫」的技術差異，就能從一個入口選擇資料來源；系統也會明確告訴他，什麼狀態才代表 AI 可以使用該內容。
