# 核心模組拆解計畫

> 目標不是為了縮短檔案而拆檔，而是依照「變更原因、失敗邊界與權限邊界」拆出可獨立測試的模組。

## 原則

- 先建立 characterization tests，再搬移程式碼。
- 每次 PR 只拆一個責任，避免同時改行為與架構。
- Public API 先保持相容，完成後再清理舊 export。
- 入口層不直接包含商業規則、SQL 或 provider 細節。
- 所有背景工作都要有明確 lifecycle、shutdown 與冪等策略。

## `server/index.ts`

### 現況問題

入口檔同時負責：

- Express app 建立與 middleware
- CSP／安全標頭
- request ID 與 HTTP log
- health／readiness
- session gate
- assets、uploads、exports
- MCP、REST v1
- realtime
- workflow／generation／agent／export／feedback runner
- boot、listen、shutdown

這會提高修改風險，也讓 app 無法在測試中被乾淨建立而不啟動網路服務。

### 目標結構

```text
server/
├── index.ts                  # process entry；listen 與 signal
├── app.ts                    # createApp(deps)
├── bootstrap.ts              # schema/seed/catalog/runner 啟動
├── lifecycle/
│   ├── startup.ts
│   └── shutdown.ts
├── middleware/
│   ├── security.ts
│   ├── requestContext.ts
│   ├── httpLogging.ts
│   └── sessionGate.ts
├── health/
│   ├── healthRoute.ts
│   ├── readinessRoute.ts
│   └── selftestRoute.ts
└── routes/
    ├── assets.ts
    ├── uploads.ts
    ├── exports.ts
    ├── mcp.ts
    ├── restV1.ts
    └── staticApp.ts
```

### 分階段

1. 抽出 `createApp()`，保留現有 route 行為。
2. 抽出 health／readiness／selftest。
3. 抽出 assets／uploads。
4. 抽出 exports。
5. 抽出 MCP／REST v1。
6. 抽出 bootstrap 與 runner lifecycle。
7. `index.ts` 最終只保留環境載入、`createApp()`、`listen()`、signal handler。

### 驗收

- [ ] `createApp()` 測試不需要占用 TCP port。
- [ ] 每個 route module 有認證與錯誤處理測試。
- [ ] `/api/health` 不碰 DB。
- [ ] `/api/ready` 保持 DB、storage、runner、provider 探針。
- [ ] graceful shutdown 保持 draining、HTTP drain、runner stop 與 timeout。
- [ ] 所有現有 E2E 無行為差異。
- [ ] `server/index.ts` 目標小於 150 行。

## `server/services/storage.ts`

### 目標結構

```text
server/storage/
├── types.ts
├── mimePolicy.ts
├── signatureSniffer.ts
├── localVolumeAdapter.ts
├── objectStorageAdapter.ts
├── signedAssetUrl.ts
├── temporaryFiles.ts
├── accessPolicy.ts
└── healthProbe.ts
```

### 邊界

- `mimePolicy`：副檔名、宣稱 MIME、magic bytes 相容性。
- `adapter`：寫入、讀取、刪除、stat，不包含 ACL。
- `accessPolicy`：使用者是否能讀取或刪除資產。
- `signedAssetUrl`：HMAC、到期時間與驗證。
- `temporaryFiles`：tmp 採用、清理、孤兒檔案。
- `healthProbe`：實際寫入／讀回／刪除。

### 驗收

- [ ] 上層 service 不直接使用本機絕對路徑。
- [ ] local adapter 與未來 S3／R2 adapter 共用 interface。
- [ ] magic bytes、MIME mismatch、SVG attachment、path traversal 有測試。
- [ ] 磁碟低水位與寫入失敗可觀測。
- [ ] signed URL 過期、竄改、錯誤資產 ID 均拒絕。
- [ ] tmp cleanup 不會刪除已採用檔案。

## `server/services/points.ts`

### 目標結構

```text
server/points/
├── types.ts
├── settings.ts
├── quotaPolicy.ts
├── usageQueries.ts
├── reservationService.ts
├── settlementService.ts
├── ledgerRepository.ts
└── errors.ts
```

### 邊界

- `quotaPolicy`：純函式，判斷 daily／weekly／group／member cap。
- `usageQueries`：只做查詢，不修改餘額。
- `reservationService`：原子預扣與 idempotency。
- `settlementService`：capture／refund／cancel。
- `ledgerRepository`：append-only ledger 與查詢。
- `settings`：管理員可調設定，不參與交易細節。

### 必要不變量

- ledger append 與餘額／quota 變更在同一交易。
- 同一 generation／workflow step 不可重複 reserve。
- 同一 reservation 不可重複 refund 或 capture。
- refund 不可超過原 reservation。
- group 與 member 用量不可跨組污染。
- 台北日界與週界定義一致。

### 驗收

- [ ] 併發 20 個預扣不會超過 cap。
- [ ] 重複 callback 只結算一次。
- [ ] 任務失敗、取消、逾時都走同一 refund API。
- [ ] 管理員調額不直接修改歷史 ledger。
- [ ] billing ledger 不受一般 Audit retention job 刪除。
- [ ] 所有生成入口、Agent、Workflow 都只能透過同一點數服務。

## PR 拆分建議

1. `refactor(server): introduce createApp without behavior changes`
2. `refactor(server): extract health and readiness routes`
3. `refactor(server): extract asset and upload routes`
4. `refactor(server): extract MCP and REST v1 routes`
5. `refactor(storage): introduce storage adapter interface`
6. `refactor(storage): split MIME and signature policy`
7. `refactor(points): extract pure quota policy`
8. `refactor(points): introduce reservation and settlement service`
9. `refactor(points): enforce idempotent ledger transitions`

每個 PR 都應附上前後架構圖、測試清單、部署風險與回滾方式。
