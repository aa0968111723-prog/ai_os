## 三、需求清單之外的盲點(建議納入路線圖)

1. **無正式資料庫遷移機制**(drizzle push 直推、無 migration 檔)——正式資料上線後改 schema 有風險;備份/還原策略也未文件化。
2. **RLS 資料庫層第二道隔離**未做(README 自列 TODO)——隔離全靠應用層,一處漏寫即跨組外洩。
3. **多數模型 `verified=false`**、影片模型/TTS 未真實測試——上線首跑可能連環失敗。
   另有測試債:9b2d22b「mock 模式不扣點」後,`e2e-auth.py` 的「彈性額度生效」與 `e2e-models.py` 的「點數已扣」兩條斷言與現行 mock 行為矛盾(FAL_MOCK 下必紅),需改為可強制走扣點的測試路徑。
4. **生成結果落地預設值需確認**——`resultUrl` 未落地為自有素材時,fal 端過期即遺失。
5. **無錯誤監控/成本異常告警**——點數消耗突增無人知;建議至少接一個錯誤追蹤+每日點數消耗摘要。
6. **後端 LLM 硬編碼 `google/gemini-flash-1.5`(舊版)**——fal any-llm 已有 gemini-2.5 系列,升級一行改動、窗口與品質更好(需真實模式驗證後切換)。
7. **助手節流是記憶體態**——多實例部署會失效;擴容前改 DB/Redis。
8. **法律/隱私文件內容不存在**——下載區已備好分類,內容需要有人產出。
9. **無帳號自助功能**——忘記密碼要管理員重設;帳號刪除/資料匯出(個資)皆無。
10. **`AUTH_MODE=dev` 後門**——已有 production 忽略保護,建議啟動自檢頁也顯著標示。
