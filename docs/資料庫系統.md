# 資料庫系統（個人 → 組 → 團隊 → 組織）

回答「可以建構一個個人／團隊／專案、甚至到最後大型組織的資料庫系統，並且連結工作台、權限系統、AI 代理系統嗎？」——可以，而且不必另起爐灶：本系統的組織模型（開發者 → 團隊 → 組別 → 個人）本來就是一棵權限樹，自訂資料庫直接掛在這棵樹的四個層級上。

## 一、這是什麼

「資料庫」＝欄位自訂的輕量結構化資料表（想像極簡版 Airtable）：

- **欄位自訂**：文字／數字／單選／日期／勾選／網址／成員／專案連結／排程連結 九種型別，必填可設，隨時增修欄位（不動 DB schema——欄位定義存 `data_tables.fields` jsonb，列資料存 `data_rows.data` jsonb）。
- **跟系統實體接起來**：「專案連結」「排程連結」欄位存實體 id，格線下拉直接挑作用組的專案／排程、顯示標題、一鍵跳到專案頁或筆記排程頁——資料庫不是孤島，一張「拍攝任務表」可以逐列掛上對應專案與拍攝日排程。
- **四層範圍**（建立時選定）：

| 範圍 | 誰看得到 | 誰能寫列 | 誰能管理（改欄位／刪庫） | 典型用途 |
|---|---|---|---|---|
| 個人 personal | 只有本人（開發者也看不到） | 本人 | 本人 | 私人待辦、靈感清單 |
| 組 group | 組成員 | 成員（可鎖為僅管理者） | 組長以上、建立者 | 器材借用表、拍攝名單 |
| 團隊 team | 團隊所有組的成員 | 成員（可鎖） | 團隊管理員、建立者 | 跨組資源表、聯絡簿 |
| 全站 global | 所有登入者 | 成員（可鎖） | 開發者（建立也限開發者） | 全組織公告、共用字典 |

- **memberWritable 開關**：組以上範圍可切成「唯讀共享」——成員看得到、只有管理者能寫，適合公告類資料。
- **專案層級呢？** 專案已有專用結構化資料（分鏡、素材、知識庫、角色卡），v1 刻意不再加「專案範圍資料庫」避免重複；專案相關清單放組範圍、名字對上專案即可。要加時只是 `scope` 多一個值＋ACL 多一個 case。

## 二、與三大系統的連結

### 1. 權限系統（單一真相：`server/services/databaseAcl.ts`）

不另設角色。`resolveTableAccess(auth, table)` 把既有 `AuthState`（組成員/組長/團隊管理員/開發者）換算成 `{canRead, canWriteRows, canManage}`：

- tRPC（網頁）與 MCP（外部 AI 代理）**走同一個函式**，不會出現「網頁擋了、AI 繞過去」。
- 無讀取權一律回「找不到」而非「無權限」——不洩漏個人庫／他組庫的存在性。
- 所有 mutation 照舊進 `audit_log`（tRPC 中介層自動記；MCP 端 `recordMcpAudit` 比照），操作紀錄頁人話字典已補齊。
- 單元測試：`databaseAcl.test.ts` 逐格驗權限矩陣。

### 2. 工作台（前端 `/databases`）

- 頂欄使用者選單「工作」區新增「資料庫」入口；頁面左欄按四層範圍列庫、右欄格線編輯（雙擊列即改、頂列直接新增、關鍵字搜尋）。
- 欄位驗證前後端共用 `shared/databaseFields.ts`（零漂移）：型別、必填、單選白名單、網址前綴、日期格式。

### 3. AI 代理系統

- **外部代理（MCP）**：新增三工具 `list_databases`（列庫＋欄位定義）、`query_database`（關鍵字查列）、`add_database_row`（寫一列，伺服器驗證型別）。金鑰擁有者是誰、權限就是誰的——與生成工具同一套 per-user 守衛。
- **站內團隊助手**（`teamAssistant.ask`）：組可見的組／團隊／全站資料庫（前 5 庫 × 各 12 列）自動注入上下文，組長可以直接問「器材借用表裡攝影機借給誰了」。個人庫刻意不進共享上下文。
- **MCP 權限也在這裡管**：每個資料庫有 `agentAccess` 等級（管理者可調，預設「可寫」）：
  - `write`＝AI 可查可寫（仍受本人權限限制，只會更嚴不會放寬）；
  - `read`＝AI 唯讀——即使本人在網頁上可寫，MCP 也不能寫；
  - `none`＝AI 完全看不到——MCP 列表不出現、團隊助手上下文也不注入。
  有效權限＝「本人權限 ∩ agentAccess」，單一真相在 `databaseAcl.resolveAgentAccess`（有單元測試）；
  結構調整（`canManage`）一律不開放給 AI 介面。
- **AI 代理（agentRuns）細部連結**：代理系統已把資料庫接進「規劃 → 執行」兩端：
  - **規劃上下文**：規劃時把此人「AI 可寫」的可見資料庫（代號 `db1`/`db2`…＋欄位 key）列進提示詞，
    讓代理能引用資料表內容規劃（例：「把每次生成的成果記進『代理成果紀錄』」）。用代號不用 uuid，防幻覺。
  - **執行步驟 `record_to_database`**：代理可把一筆結果寫進指定資料庫。落地前對照組可寫庫解析 `dbRef→tableId`，
    執行時再驗一次現況並套 `resolveAgentAccess`（`none`/`read` 皆不可寫）——與 MCP 同一道守衛。
  - 列寫入走 `services/databaseCore.addDataRowValidated`（tRPC / MCP / 代理 / REST 的**單一路徑**，驗證與保險絲永遠一致）。

## 二點五、專案・排程・外部系統的連結

### 專案 × 資料庫（雙向）
- 欄位型別「專案連結」把一列指到某專案；專案頁的「關聯資料庫」卡（`databases.linkedToProject`）反向列出
  「哪些資料表的哪些列提到這個專案」——例如器材借用表裡指派給本片的器材、任務表裡本片的待辦。唯讀彙整、無連結不顯示。

### 排程 × 資料庫 → 手機/桌面日曆
- 欄位型別「排程連結」把一列指到某組排程項。
- **行事曆訂閱**：有「日期」欄位的資料庫可訂成 `.ics`（`GET /api/databases/:id/calendar.ics?key=<個人金鑰>`）——
  每個有日期的列變成一個事件，加進手機/桌面日曆的「訂閱行事曆」即持續同步（金鑰走查詢字串，因日曆訂閱不能帶標頭）。

### 本機・手機・其他資料庫的連接
統一用**個人連線金鑰**（`aidmcp_…`，在「怎麼用」頁自助建立、可撤銷）認證，權限＝金鑰擁有者本人 ∩ `agentAccess`：
- **REST API v1**（`server/services/restApi.ts`）：任何能發 HTTP 的客戶端都能連——
  - `GET /api/v1/databases`（列庫）、`GET /api/v1/databases/:id/rows`（查列，支援 `?q=`/`?limit=`/`?offset=`）、
    `POST /api/v1/databases/:id/rows`（新增，body `{"data":{…}}`）。
  - 用途：本機腳本（curl/Python）、手機 App、Google 試算表 Apps Script、其他資料庫的 ETL 同步。
- **CSV 匯入匯出**（連接 Excel／Google 試算表／其他資料庫）：
  - 匯出 `GET /api/databases/:id/rows.csv`（表頭＝欄位名；工作台「匯出 CSV」鈕直接下載）。
  - 匯入 `databases.importCsv`（貼上 CSV → 對應欄位 → 逐列走同一套驗證；回「成功幾列、失敗哪幾行為什麼」，部分失敗不整批中止）。
  - CSV 解析/序列化在 `shared/csv.ts`（RFC 4180，含引號轉義與 round-trip 測試）。
- 授權一律沿用 `databaseAcl`：REST/CSV/日曆對「無讀取權」的庫一律回 404（不洩漏存在性），
  金鑰視為「AI 介面」套 `resolveAgentAccess`——外部連線不會比網頁看到更多。

## 三、檔案與外部來源（AI 怎麼讀）

資料庫除了列資料，每個庫還能掛「文件」——AI 可讀檔案層（`data_files`）。設計核心：**匯入當下抽一次純文字，AI 永遠讀抽好的文字**，不在每次問答時重新解析原檔。

### 匯入的三條路

| 路徑 | 支援 | 說明 |
|---|---|---|
| 檔案上傳 | txt／md／csv／json／html／srt／vtt（純解析）＋ **PDF**（pdf-parse）＋ **DOCX**（mammoth） | 其他格式（圖片/影音/zip）照存但標「僅存檔」，AI 讀不到內文 |
| 網址匯入 | Google 文件→txt、試算表→csv、簡報→txt、雲端硬碟→直載；一般網頁→HTML 轉純文字 | Google 需「任何人知道連結都能檢視」；私有檔會收到人話錯誤提示 |
| Notion | 官方 API（環境變數 `NOTION_TOKEN`＋頁面「分享給整合」） | 逐層抓 blocks 轉純文字；沒設 token 時提示改用 Notion 匯出檔上傳 |

網址匯入的來源記在 `sourceUrl`，之後可一鍵「重新整理」重抓最新內容（配額以增量把關）。

### AI 讀取設計（兩個介面、同一套權限）

1. **MCP 代理（Claude 等外部 AI）**——完整讀取：
   `list_database_files`（列文件＋可讀字數；`keyword` 過濾內文並回匹配片段）→
   `read_database_file`（讀抽出的純文字，單次 20,000 字、`offset` 分頁，回應含 `totalChars`/`hasMore`）。
   長文的正確用法是「先 keyword 定位、再分頁讀」，不是一次灌整本。
2. **團隊 AI 助手**（無工具可用，靠上下文注入）——摘要級：每庫附「文件名清單＋最近兩份可讀文件各 600 字摘錄」，
   常見問題（名單、日程、開示重點）直接答得出；要深讀全文請走 MCP。

權限與資料列同一套：文件跟著資料庫的範圍與 `agentAccess` 走——`none` 的庫連文件都看不到、`read` 可讀不可寫；
上傳需列寫入權、刪除限上傳者或管理者。

### 配額與安全

- **每人 5GB**（跨庫合計、按上傳者計）：`settings.fileQuotaGb` 開發者可調（0＝不限），管理頁「點數與額度」卡有欄位；刪文件即時釋放。
- 疊加既有磁碟守門（單檔上限＋磁碟保留水位）；網址匯入另有 25MB 抓取上限與 25 秒逾時。
- **SSRF 防護**：只允許 http(s)、擋 localhost 與私有網段字面位址（127/10/192.168/172.16-31/169.254/100.64-127/0.0.0.0、IPv6 loopback/ULA/link-local）；
  已知限制：不做 DNS 解析比對（內部工具威脅模型；擴大部署時應改走出口代理白名單）。
- 抽出文字上限 300,000 字；抽取失敗不擋存檔（之後格式擴充可補抽）。

### 之後可再深化

- **RAG 檢索**：目前是「全文＋分頁讀」；文件量大後可對 `text_content` 建 embedding 索引，AI 導演引用開示稿即走檢索（README 路線圖既有項目的自然延伸）。
- **OAuth 雙向同步**（Google/Notion 私有內容自動更新）：目前刻意不做（零 OAuth 基建達八成價值，見優化評估報告）；`sourceUrl`＋重新整理已覆蓋「來源改了要更新」的主場景。
- XLSX：先用 Google 試算表連結（→csv）或另存 CSV 上傳。

## 四、往「大型組織」的擴展路線

現在的設計已為放大預留了位置，依序打開即可：

1. **量級**：`data_rows` 有 `(table_id, created_at)` 索引＋單庫 2 萬列保險絲；超過時（a）調高保險絲並在 `data.data` 上建 GIN 索引供 jsonb 查詢、（b）列表已是 offset 分頁、關鍵字走 SQL 而非撈全表。
2. **組織層**：目前「全站」＝單一組織。要多組織（多基金會共用一套系統）時，加 `organizations` 表、`teams.orgId`、`scope: "org"`——ACL 只多一個 case，資料表不動。
3. **RLS 第二道防線**：README 路線圖既有項目。應用層守衛已把 `groupId/teamId/ownerId` 正規化存欄位（不埋在 jsonb），未來直接對 `data_tables`／`data_rows` 上 Postgres RLS policy。
4. **欄位進階型**（關聯到另一庫的列、多選、附件）：`fields` 是 jsonb，加型別＝改 `shared/databaseFields.ts` 一處驗證＋前端一個輸入元件，無遷移。
5. **匯入匯出**：列資料是規整 jsonb，CSV 匯出／匯入是純 router 工作；「資料下載」頁可直接掛。
