# AIOS 專案頁：故事內嵌生成與按需細修計畫

> 狀態：已確認的產品方向／待分階段實作  
> 適用路由：/p/:id  
> 主要裝置：手機直向優先，並支援桌機  
> 決策日期：2026-08-14

## 1. 決策摘要

專案頁不再以「故事 → 分鏡 → 製作 → 成片」四個大型頁籤推動使用者逐步設定。

新的核心原則是：

> 整個專案以故事為唯一主畫面。角色、場景、道具、分鏡、製作與交付全部收合在故事區內；先讓 AI 依目前資料一鍵生成影片，使用者看完結果後，只展開不滿意的部分細修。

預設路徑從「設定完全部內容才能生成」改為：

1. 寫下或貼上故事。
2. AI 在背景整理角色、場景、道具與分鏡。
3. 使用者按一次「生成影片」。
4. 直接觀看成果。
5. 不滿意時，才展開角色、場景、分鏡或製作設定。
6. 只重新生成受影響的鏡頭。
7. 滿意後在同一頁展開交付。

若本文件與 PROJECT_WORKSPACE_STORY_FIRST_REFACTOR.md 的「四個主要階段」或 Storyboard/Production/Final 獨立工作區方向衝突，以本文件的單一故事主畫面與按需展開方向為準。既有文件中的資料安全、相容性、授權、生成閘門、可撤銷與測試要求仍保留。

## 2. 為什麼要改

目前專案頁已具備真實能力，但主要問題是能力被拆成太多頁面和大型卡片：

- 故事、分鏡、製作、成片需要反覆切換。
- 使用者在看到第一個成果前，被要求理解角色庫、場景庫、素材庫、知識庫、模型與交付設定。
- 手機畫面同時有階段導航、全站底部導航、AI 光球、留言入口與多層卡片。
- 分鏡卡、製作狀態、完成度與交付資訊在不同位置重複呈現。
- 使用者真正想做的是「先做出來看看」，而不是先完成一輪資料庫管理。

這次重構不是刪除能力，而是把能力改成按需揭示。

## 3. 產品不變式

實作不得破壞以下規則：

1. 故事是唯一的主畫面，不再保留四階段作為主要導航。
2. 預設畫面只突出故事、目前準備狀態、單一生成按鈕與最新成果。
3. 角色、場景、道具、分鏡、製作、交付預設收合。
4. 使用者不必先進入任何資料管理器，便能產生第一版影片。
5. AI 高信心結果可在背景建立；只有真正不確定或阻擋生成的內容才詢問。
6. 生成後先看成果，不強迫逐鏡審核。
7. 細修必須從成果回到具體問題，且只重新生成受影響範圍。
8. 不建立第二套角色、場景、分鏡、候選或交付資料來源。
9. 保留既有權限、額度、核准、冪等、版本、撤銷、協作與生成供應商能力。
10. 手機上不得因巢狀收合、浮動按鈕或固定導航遮住內容與主 CTA。

## 4. 目標介面

### 4.1 專案預設狀態

使用者進入 /p/:id 後，主內容依序為：

1. 精簡專案標頭：名稱、保存狀態、協作者、更多。
2. 故事編輯器：保留自動儲存、共同編輯、解析摘要。
3. 收合摘要列：角色、場景、道具、分鏡、製作、交付。
4. 準備狀態：可生成／有少數項目需確認／無法生成。
5. 唯一主 CTA：「生成影片」或「繼續生成」。
6. 最新影片預覽與結果回饋入口。

預設不顯示：

- 四階段頁籤。
- 完整角色／場景／素材管理卡。
- 全部分鏡卡。
- 模型矩陣與 AI 職能卡。
- 完整製作統計。
- 分享與交付表單。
- 重複的 AI／留言浮動按鈕。

### 4.2 收合列

故事下方使用同一組可揭示的摘要列：

| 收合項目 | 收合時顯示 | 展開後可做 |
| --- | --- | --- |
| 角色 | 數量、需確認數、一致性警告 | 查看／修改身份、外觀、造型、參考圖與出現鏡頭 |
| 場景 | 數量、環境狀態、缺漏 | 查看／修改地點、時間、天氣、光線、風格與出現鏡頭 |
| 道具 | 數量、重要道具警告 | 查看／修改外觀、持有人與出現鏡頭 |
| 分鏡 | 場數、鏡數、可生成數 | 查看縮圖、敘述、秒數、角色／場景引用與鏡頭狀態 |
| 製作 | 已完成／生成中／失敗／待核准 | 查看所選鏡頭的畫面、影片、配音、音效與版本 |
| 交付 | 完成度與缺少項目 | 預覽整片、匯出、素材包、LumaFusion、分享與審核 |

整列點擊即可揭示，不需要換路由或切換主頁籤。

### 4.3 展開層級限制

避免把複雜度藏進多層手風琴：

- 頁面最多只有兩層可見階層：故事主畫面 → 一個展開區。
- 同一時間手機預設只展開一個主要區。
- 在分鏡區點擊單一鏡頭後，細節使用底部抽屜或全螢幕編輯層，不再建立第三層行內手風琴。
- 角色、場景或道具的深度編輯同樣進入抽屜／全螢幕層，關閉後回到原捲動位置。
- 桌機可使用右側 Inspector，但資料與操作契約必須與手機抽屜相同。

## 5. 一鍵生成影片

### 5.1 使用者體驗

「生成影片」不是假按鈕，也不是只建立分鏡。它是既有能力上的統一編排入口：

1. 儲存目前故事。
2. 只解析自上次成功解析後有變動的內容。
3. 建立或更新必要的角色、場景、道具連結。
4. 建立缺少的 Scene／Shot 草稿，不覆蓋使用者已細修的鏡頭。
5. 計算哪些鏡頭已可生成，哪些被真正的阻擋條件卡住。
6. 對可生成鏡頭走既有生成閘門、額度、核准與供應商流程。
7. 在同一頁顯示背景進度、部分成功與失敗。
8. 生成完成後直接呈現可播放成果。

若現有額度或核准規則要求確認成本，沿用既有必要確認；不得再增加一個與真實閘門無關的「流程確認」頁。

### 5.2 阻擋與非阻擋項目

阻擋生成的項目才中斷使用者，例如：

- 故事為空。
- 必要的模型／供應商不可用且沒有既有 fallback。
- 權限、額度或核准未通過。
- 某鏡缺少生成契約要求的必要輸入。

下列項目不應阻擋第一版：

- 尚未細修鏡頭語言。
- 尚未選擇進階鏡頭參數。
- 角色或場景只有 AI 高信心預設。
- 尚未補齊非必要音效。
- 尚未開啟專業模式。

對非阻擋缺漏，AI 使用可追溯的預設並標記為可回頭細修。

### 5.3 局部重生

修改後不得預設重做整部影片：

- 改單一 Shot：只標記該 Shot 相關產物過時。
- 改角色造型：找出引用該 Look 的 Shots，先顯示影響範圍。
- 改場景環境：找出引用該 EnvironmentState 的 Shots。
- 改故事但未影響既有 Shot：不得無理由使全部產物失效。
- 任何昂貴的批次重生都必須先顯示 Change Preview，並可取消。
- 已選定的 current generation 不得被背景完成的候選靜默覆蓋。

## 6. 成果優先的修正循環

影片預覽旁提供單一「哪裡需要修改？」入口。使用者可以：

- 點選時間軸中的問題鏡頭。
- 使用自然語言描述，例如「角色長得不一樣」「海灘不像淡水」「動作太僵硬」。
- 讓 AI 提出問題來源，但 Proposal 不等於修改。
- 使用者選擇 Apply／Adopt 後，才寫入角色、場景、分鏡或製作設定。
- 修改完成後只重新生成該鏡或受影響鏡頭。

問題來源與展開位置的對應：

| 回饋 | 優先展開 |
| --- | --- |
| 人物長相、服裝、不一致 | 角色 |
| 地點、天氣、光線、時段錯誤 | 場景 |
| 構圖、敘事、運鏡、秒數不對 | 分鏡 |
| 動態、口型、配音、音效或模型輸出不佳 | 製作 |
| 整體節奏或故事順序不對 | 故事／分鏡 |
| 下載、分享、素材缺少 | 交付 |

AI 不確定問題來源時，只給建議與可選項，不得直接大規模改寫資料。

## 7. 對現有程式的遷移方式

此次方向應建立在現有實作上，不重做第二套。

| 現有區域／能力 | 新位置或責任 |
| --- | --- |
| ProjectPage.tsx | 保留路由、載入、權限與專案殼；移除四階段作為主導航 |
| StoryStage.tsx | 升級為單一故事主畫面與所有收合區的宿主 |
| StoryStage 解析 chips | 改成可點擊的角色／場景／道具摘要與揭示入口 |
| ProjectStageNav | 從主要流程移除；必要時暫作舊深連結相容層 |
| SceneList／StoryboardStage／SceneStudio | 以收合分鏡摘要與 Shot 抽屜方式嵌入 StoryStage |
| CreationWorkbench | 保留真實生成能力，透過 selected Shot adapter 在製作抽屜內使用 |
| Character／Scene／Prop managers | 保留資料與 mutation，改由故事摘要列按需載入 |
| projectContextNav reveal events | 目標改成開啟對應收合區或深度編輯抽屜 |
| Production workspace | 變成分鏡／製作摘要與每鏡狀態，不再是獨立主頁 |
| Final workspace | 變成交付收合區，不再是獨立主頁 |
| AI assistant | 改為當前故事／實體／Shot／成果感知的單一操作入口 |
| 現有 route anchors | 保留相容轉接，舊連結導向相應收合區 |

實作前需再次盤點實際元件名稱與依賴，但不得用盤點作為新建平行系統的理由。

## 8. 資料與狀態原則

第一階段優先沿用現有 Story、Scene、Shot、Character、CharacterLook、Location／Scene preset、Prop、Generation、Asset 與交付資料。

- 不為了收合 UI 新建資料庫表。
- 收合狀態是 UI 狀態，不進核心業務 schema。
- 若需要記住上次展開位置，優先使用 URL search param 或既有偏好儲存機制。
- 生成編排要沿用既有 command／queue／idempotency／approval／quota。
- 一鍵生成每次操作要有可追蹤 execution／batch 身分，重新整理後仍可恢復真實進度。
- 部分失敗不得抹除已成功成果。
- 角色、場景與分鏡的引用關係必須可反查，才能做正確的局部失效與局部重生。

## 9. 響應式與互動要求

### 手機

- 390px 寬可完成故事輸入、生成、觀看、定位問題、細修與重新生成。
- 故事編輯器優先，不先顯示大型管理卡。
- 主要觸控區至少 44px。
- 展開區與底部抽屜不得被全站 bottom nav、AI 浮球或留言按鈕遮擋。
- 只保留一個 AI 入口與一個主要 CTA。
- 鍵盤開啟時故事編輯與儲存狀態仍可見。
- 不得出現水平溢位。

### 桌機

- 故事仍是中心，不重新變成多欄 ERP。
- 可使用右側 Inspector 顯示已選角色／場景／Shot。
- 分鏡時間軸可放大，但不得形成第二個獨立的完整工作台路徑。
- 與手機共用相同資料與操作契約。

## 10. 分階段實作 PR

遵守一個 PR 解決一個主要風險，不把整個重構一次塞入同一支 PR。

### PR 1：單一故事主畫面骨架

- 移除四階段主要導航。
- StoryStage 成為唯一主內容。
- 建立六個收合摘要列與唯一主 CTA 位置。
- 保留舊 anchor／深連結相容。
- 暫時把既有能力接回收合區，不改生成後端。

驗收重點：沒有功能消失、手機首屏明顯縮短、可從舊入口到達原能力。

### PR 2：角色／場景／道具按需揭示

- 解析 chips 可點擊。
- 管理器 lazy mount。
- 深度編輯使用共用抽屜／Inspector。
- 關閉後回到原故事位置。

驗收重點：不用離開故事即可看與改資料，不產生第二資料來源。

### PR 3：分鏡與製作內嵌

- 分鏡摘要列顯示場／鏡／準備狀態。
- Shot 點擊後開啟細修抽屜。
- CreationWorkbench 透過所選 Shot 接入。
- 保留版本、核准、成本、重試與 current pointer 不變式。

驗收重點：從故事到某一鏡生成不需切換主頁。

### PR 4：一鍵生成編排

- 建立真實 generation batch／execution。
- 增量解析、補齊 ShotDraft、ready/blocked 計算。
- 背景進度、部分成功、重整恢復與冪等。
- 完成後直接顯示成果。

驗收重點：使用者不先開任何收合區也能得到第一版影片。

### PR 5：成果診斷、局部細修與交付

- 成果回饋定位到故事／角色／場景／分鏡／製作。
- Change Preview、Apply／Adopt 與 Undo。
- 依賴感知 stale 與局部重生。
- 交付收合區接回真實匯出／分享能力。

驗收重點：不滿意只修問題範圍，滿意可在同頁交付。

## 11. 測試與驗收

### 關鍵使用者流程

1. 新專案貼入故事，不展開任何設定。
2. AI 解析完成，只對真正不確定項目詢問。
3. 點一次「生成影片」。
4. 可看到真實生成進度與部分成功狀態。
5. 完成後直接播放成果。
6. 點問題鏡頭，修改角色或場景。
7. 系統顯示受影響鏡頭，不靜默重生整片。
8. 只重生受影響鏡頭。
9. 在同頁展開交付並輸出。

### 回歸要求

- 舊專案資料不為空、不遺失。
- Story autosave 與 realtime collaboration 不退化。
- 解析候選、撤銷與 uncertainty 流程仍有效。
- 權限、group scope、quota、approval、provider routing 與 points 不被繞過。
- generation retry 維持冪等，不重複扣點。
- 候選完成不覆蓋人類已選 current。
- 舊 anchor／事件／返回路徑有相容測試。
- 390、430、768、1280、1440 寬度通過視覺與操作檢查。
- 無水平溢位、浮動控制遮擋或鍵盤碰撞。

各實作 PR 依實際變更執行並誠實回報：

~~~bash
npm run typecheck
npm run check:boundaries
npm run check:ui-primitives
npm run check:hooks
npm test
npm run test:client
npm run build
~~~

若只改規劃文件，PR 必須明確標示未執行 runtime 測試，不能假稱通過。

## 12. 成功指標

產品發布後應觀察：

- 從進入專案到按下第一次生成的時間。
- 第一次生成前被迫開啟的設定區數量，目標為 0。
- 生成後能否從問題鏡頭直接到正確細修區。
- 局部重生占比與不必要整片重生率。
- 手機上完成「故事 → 生成 → 修一鏡 → 再生成」的成功率。
- 因入口重複、遮擋或找不到返回路徑造成的放棄率。

## 13. 明確排除

本計畫只處理故事區、分鏡、生成、成果修正與交付的單一頁體驗，暫不混入：

- 全站首頁重構。
- 獨立筆記／排程系統重構。
- 社群、聊天、Admin 或身份驗證。
- 新的影片剪輯器／NLE。
- 新的 AI provider 或模型市場。
- 與此路徑無關的資料庫大遷移。
- 純視覺換皮但沒有真實能力接線的 mockup。

筆記與排程未來可綁定 Project／Scene／Shot，但應另開計畫，不能阻擋本計畫的成果優先主流程。

## 14. Definition of Done

整體方向完成時：

- /p/:id 預設只呈現故事主畫面。
- 四階段不再是主要導航。
- 角色、場景、道具、分鏡、製作、交付全部可在故事內按需展開。
- 使用者不打開任何細修區也能產生第一版影片。
- 完成後直接觀看，不必先逐鏡審核。
- 不滿意可從成果定位到正確細修區。
- 修改會顯示影響範圍，並能局部重新生成。
- 滿意可在同一頁完成交付。
- 所有真實既有能力、資料、權限、成本、核准、版本與協作仍有效。
- 手機直向可完成完整主要流程。
- 沒有新平行資料來源、假按鈕或只做外觀的占位功能。
