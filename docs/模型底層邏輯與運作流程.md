## 1. 站內生成管線（先對齊產品）

```
使用者提示詞 + 世界觀（禁忌／正向補強）
        │
        ▼
effectivePromptParts → { positive, negative }
        │
        ▼
model.input(positive, aspect, sourceUrl)  // 各模型 schema 映射
        │
        ▼
若 supportsNegativePrompt(model) 且 negative 非空
  → falInput.negative_prompt = negative   // generationCore
        │
        ▼
fal queue: submit → poll status → result
        │
        ▼
extractResult → 落地素材 / 點數結算
```

**重點**：多數模型的 `input()` 只送 `prompt` + 尺寸／比例（及 needs 來源）。  
步數、CFG、`rendering_speed`、`style` 等進階旋鈕目前吃 **fal 官方預設**——這是產品簡化，不是模型沒有這些參數。

## 2. 自注意力：共同心臟

幾乎所有現代生成模型（LLM、FLUX、影片 DiT、TTS）都建立在 Transformer + Self-Attention。

### 單一注意力頭

給 token 矩陣 \(X\)，投影為 Query／Key／Value：

\[
Q = XW_Q,\quad K = XW_K,\quad V = XW_V
\]

\[
\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
\]

- \(QK^\top\)：每個位置問「誰和我有關」
- \(\mathrm{softmax}\)：變成混合權重
- 乘 \(V\)：加權彙整資訊

第 1 層起即可全局互通（不像 CNN 要堆很多層才有大感受野）。

### 交叉注意力 vs Joint Attention

| 機制 | 做法 | 典型 |
|------|------|------|
| Cross-Attn | 圖 token 當 Q，文 token 當 K/V | 舊式 U-Net 文生圖 |
| Joint / Multi-modal Attn | 圖+文串成同一序列做自注意力 | **FLUX** Double/Single Stream |

### LoRA 在底層做什麼

不重訓整顆網路，只在注意力（與／或 MLP）權重加低秩更新：

\[
W' = W + BA,\quad r \ll d
\]

對應目錄：`fal-ai/flux-lora`、`fal-ai/flux-2/lora`、`fal-ai/lora`（SDXL 基座）。

## 3. 潛空間 VAE

直接在 \(1024\times1024\times3\) 像素上做生成成本極高。主流：

```
原圖 x → Encoder E → 潛變數 z（空間縮小、通道壓縮）
在 z 上做擴散／flow → Decoder D → 像素
```

站內的 `image_size`／`aspect_ratio` 最終影響 latent 網格大小，再 decode 回像素。

---

## 4. 兩大生成範式

### A. 經典擴散（DDPM 系）

前向加噪：

\[
x_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\varepsilon
\]

訓練預測噪聲 \(\varepsilon_\theta\)；取樣多步去噪（常 20–50+ 步）。

**目錄代表**：SDXL Lightning、Kolors、Playground、`fal-ai/lora`。

### B. Flow Matching / Rectified Flow（FLUX 系）

學**速度場** \(v_\theta\)，沿近似直線路徑把噪聲運到數據：

\[
z_t = (1-t)\,x + t\,\varepsilon
\]

\[
\mathcal{L} = \mathbb{E}\big[\|v_\theta(z_t,t,c)-(\varepsilon-x)\|^2\big]
\]

取樣是 ODE，路徑更直 → **更少步**仍可用：

| 模型 | 典型步數 |
|------|----------|
| FLUX.1 [schnell] | 1–4（蒸餾） |
| FLUX.1 [dev] | ~28 |
| FLUX.2 [flex] | 10–50（可調） |

**為何 FLUX 主端點不進 `NEGATIVE_PROMPT_SUPPORTED`**：  
官方 schema 多半無 `negative_prompt`；條件注入與舊式 CFG 假設不同。誤送易 422。

## 5. 骨幹：U-Net vs DiT vs FLUX 雙流

### U-Net

下採樣 → 瓶頸 → 上採樣 + skip。歸納偏置強、中小模型穩。  
→ SDXL / Lightning / 部分舊擴散。

### DiT（Diffusion Transformer）

Latent 切 patch → token → Transformer blocks（常以 AdaLN 注入時刻／條件）→ unpatch。  
擴展性好、長距離依賴強。**影片模型幾乎都走時序 DiT。**

### FLUX：Double-Stream + Single-Stream

1. **Double-Stream**：圖、文各有權重；attention 在串接序列上混合  
2. **Single-Stream**：圖文同一套權重繼續交互  
3. 丟掉文 token → decode 圖像

這就是「12B flow transformer」的具體結構（非 U-Net）。

## 6. Classifier-Free Guidance（CFG）

\[
\hat\varepsilon = \varepsilon_\emptyset + s\cdot(\varepsilon_c - \varepsilon_\emptyset)
\]

- \(s\) 即 `guidance_scale`（FLUX.1 dev 預設約 3.5；FLUX.2 dev 約 2.5）  
- 過高易過飽和、假  
- 站內多數未暴露 → 永遠吃官方預設

**Negative prompt** 在舊擴散常實作為「推離負向概念」；不是所有架構都有穩定欄位 → **必須 allowlist**（見 `supportsNegativePrompt`）。

## 7. 三條生圖哲學（對目錄很重要）

| 哲學 | 機制 | 目錄代表 |
|------|------|----------|
| 擴散／Flow 生成 | 從噪聲積分到圖像 | FLUX、SDXL、Kolors、AuraFlow、Seedream、Qwen-Image |
| 多模態 LLM 渲染 | Gemini 級理解意圖再出圖 | **Nano Banana 2 / Pro** |
| 設計／排版特化 | 文字渲染、向量、版面 | Ideogram、Recraft |

Nano Banana 吃 `aspect_ratio`、可掛參考圖、SynthID 浮水印；**不是** steps/CFG 那套旋鈕世界。

---

## 8. 影片：時間也是注意力軸

文生影／圖生影（Veo、Kling、Wan、LTX、Seedance…）：

- Token ≈（時間, 高, 寬）上的 patch  
- 空間／時間（或分離的）self-attention  
- 條件：文字、首幀、首尾幀  

貴、慢、易身份漂移：要在跨幀注意力裡鎖角色，比單張難一個數量級。

---

## 9. 蒸餾（Lightning／Schnell）

老師多步軌跡 → 學生 1–8 步逼近同一終點。  
代價：細節上限與可控性通常低於老師。

## 10. 參數 ↔ 底層意義

| 站內／fal 參數 | 底層意義 |
|----------------|----------|
| `num_inference_steps` | ODE/SDE 積分步數 |
| `guidance_scale` | CFG 強度 |
| `negative_prompt` | 擴散系常見；flow／LLM 系常無 |
| `image_size` | latent 網格 → 輸出解析度 |
| `aspect_ratio` | 固定比例下由服務選像素（Imagen、Nano Banana） |
| `loras[].scale` | 低秩適配強度（常見 0.6–1.2） |
| `seed` | 初始噪聲 RNG，可重現 |

## 11. 家族地圖（速查）

```
自注意力 / Transformer
  ├─ VAE 潛空間
  ├─ 擴散(ε) + U-Net ── SDXL / Lightning / SD LoRA
  ├─ Flow(v) + Double/Single Stream ── FLUX.1/2 全家
  ├─ 開源 flow ── AuraFlow
  ├─ 統一生成+編輯 ── Seedream / Qwen-Image 系
  ├─ 多模態 LLM 出圖 ── Nano Banana（Gemini Image）
  └─ 時序 DiT ── Veo / Kling / Wan / LTX …
```

## 12. 這份研究在站內的三個落點

本文件是人看的版本；使用者在畫面上看到的，是同一份研究的三個機器可讀落點。

| 落點 | 模組 | 回答的問題 |
|------|------|------------|
| **底層模型（基座身分）** | `shared/modelBase.ts` | 這條 fal 端點背後是誰家的哪顆權重？開源還是只有 API？ |
| **運作流程（這類怎麼跑）** | `shared/modelMechanics.ts` | 提示詞進去之後，一關一關發生了什麼？ |
| **文字窗口（讀得進多少）** | `shared/textEncoders.ts` | 文字塔是什麼、窗口多長、超出會被截掉嗎？ |

`shared/modelBase.ts` 存在的理由：目錄的 `id` 是**端點**不是**模型**。
`fal-ai/flux/dev`、`fal-ai/flux-lora`、`fal-ai/flux/dev/image-to-image` 是同一顆 FLUX.1 [dev] 的三個入口——
換過去風格不會變，換基座才會。這件事清單、比較表、熱力圖與競技場都要看得到，
否則使用者會把「換個端點」誤當成「換個模型試試」。

三者共用同一條誠實規則：**官方沒公開就標「未公開」，不填估算值**
（`weights: "unknown"`、`limitTokens: undefined`）。`shared/modelBase.test.ts` 守住
「每顆現役模型都查得到基座」與「閉源模型不得宣稱參數量」。

使用者端的三種用法（`/models` 模型指南）：

- **比較表**：底層模型／出品方／骨幹架構／權重四列擺在規格最上面。
- **分析熱力圖**（`shared/modelHeatmap.ts`）：整類攤成「模型 × 指標」，
  規格欄（點數／窗口／可控性／健康／查證）＋ 實測欄（我的成功率／速度／用量）。
  沒有資料的格子畫成斜線空格，**不是 0 分**——未公開的窗口與很短的窗口是兩件事。
- **實測競技場**（`generation.bench` / `benchResult`）：同一個提示詞送進 2–4 顆模型各跑一輪，
  並排看成品、點數與耗時。走的是與一般生成完全相同的送出路徑（估點、審核門檻、ACL、退點），
  不是繞過去的捷徑。

## 13. 維護約定

1. 新模型入目錄前：查 fal OpenAPI／llms.txt 是否有 `negative_prompt`，再決定 allowlist。  
2. `input()` 參數名必須對齊官方（例：Recraft 用 `size` 非 `image_size`——見研究卡落差）。  
3. `verified: false` 的端點以 `scripts/probe-fal-endpoints.ts` 連通探測後再升 true。  
4. 底層研究更新時同步改本文件、`shared/modelBase.ts` 與 `docs/research/model-deep-dive-2026-08/`。  
5. 新家族入目錄時 `shared/modelBase.test.ts` 會紅（查不到基座）——補規則，不要放寬測試。
