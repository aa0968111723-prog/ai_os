## C. 超出本次範圍的技術缺口(建議團隊後續處理,勿在指南層硬塞)

> 這些是**目錄本身**的缺口/待驗,牽動 267 條主目錄與計價,屬 fal 生態研究範疇,本次刻意不動,
> 只如實記錄。修正前請先用下方 D 的連通探測 + 單模型實測確認。

1. **i2v 缺領頭羊**:Seedance 2.0 目前只有 `text-to-video`,無 `image-to-video`;而外部 2026 排行榜(Artificial Analysis)其 i2v 為 #1。圖生影片類目前止於 Seedance 1.5 Pro。建議補 Seedance 2.0 圖生旗艦條目。
2. **Z-Image 缺文生圖端點**:通義 Z-Image-Turbo(2026-01)為開源 Image Arena #1,目錄只有 `z-image-trainer`(訓練),缺 t2i 生成端點——一個強力經濟檔付之闕如。
3. **Imagen 4 slug 可能過時**:仍走 `imagen4/preview/...`;2026 年中 Imagen 4 應已 GA,`preview` 恐失效,需重新確認端點。
4. **verified:false 但已確認為真實的模型**(建議實測後升 verified):Seedream 5.0 Pro、Hunyuan Image 3.0、Index TTS 2.0、Scribe v2、Thera、image-editing 系列。
5. **MiniMax Music 版本漂移**:目錄旗艦標 `minimax-music/v2.6`(verified=false、估 $0.15);外部 2026 為 Music 2.5,fal 實價約 $0.035/次——slug 與價格都需首跑校正。
6. **Kling 3.0 slug**:以推定 `o3` 引用;外部通稱「Kling 3.0」,需確認 fal 實際 slug 為 `o3` 或 `v3`。
7. **Bria RMBG 去背被低估**:2026 Bria benchmark 複雜背景勝 BiRefNet(90% vs 85%),文案可再強化。

## D. fal 端點「連通性」實測計畫(工具已交付,本沙盒無法執行)

需求:確認站上每個 fal 模型「叫得動」——**管道通就好,不需要真的生成**。

- **工具**:`scripts/probe-fal-endpoints.ts`。做法是對每個端點送空輸入 `{}`,靠 fal 在**進算力前**
  以 422/400 擋下來證明「端點存在＋金鑰通＋路由通,且未生成」(fal 不對驗證失敗計費);少數
  接受空輸入而排入佇列者會**立即取消**,絕不留下生成任務。
- **狀態判讀**:422/400 = ✅ 連通未生成;200/202 = ✅(已取消);404 = ❌ 端點不存在(該修 id);
  403 = ❌ 無權限;401 = ❌ 金鑰無效;5xx/逾時 = ⏳ 暫時性。
- **為何本次未跑**:此開發沙盒(a)未設 `FAL_KEY`,(b)網路政策封鎖對 `queue.fal.run` 的連線
  (gateway 回 403)。故只交付工具,**未捏造任何實測結果**。
- **怎麼跑**(在有金鑰、能連 fal 的環境,如正式部署):
  ```bash
  npx tsx scripts/probe-fal-endpoints.ts               # 乾跑:列出 253 個唯一端點,不連網
  FAL_KEY=... npx tsx scripts/probe-fal-endpoints.ts --yes    # 真實批次連通探測(不生成)
  ```
  產出 `docs/fal端點連通報告.md`:逐端點連通狀態,並標出 404(該修 id)與 403(該開通)。
- **連通 ≠ 已驗證**:連通只證明「叫得動」;要把 `verified` 改 `true` 仍需一次真實生成確認輸出正常
  (`scripts/verify-models.ts --probe "<id>" --yes`,會扣費),此為既有的單模型實測流程。
