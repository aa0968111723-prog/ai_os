## 一、這個系統是什麼（30 秒版）

一個網站：夥伴登入 → 選自己的組 → 建立影片專案 → 填「世界觀」（一句話故事/關鍵訊息/調性）→ 之後每次 AI 生成**自動帶入這些背景**（不用重複解釋）→ 生成的圖/影片加入分鏡、排順序 → 送組長審批 → 打包下載素材包 → 去剪映/Premiere 完成成片。

## 二、系統運作邏輯（給看得懂一點技術的人）

```
瀏覽器（React）──HTTPS──▶ Railway App（Express+tRPC）──▶ Railway Postgres（資料）
                                    │
                                    └──▶ Fal.ai（唯一 AI 供應商：圖像/影片/建議）
```

- **一個網址搞定**：網頁、API、下載、MCP 都在同一個服務
- **假生成模式**：沒填 FAL_KEY 時系統照樣能用（生成回測試圖、不花錢）——先讓夥伴熟悉流程，之後填金鑰即切真實生成
- **多組隔離**：每筆資料掛組，別組永遠看不到（34 項自動測試驗證過）

## 三、怎麼部署上線（Railway，約 15 分鐘）

1. 到 railway.app 登入（用 GitHub 帳號）→ New Project
2. **加 Postgres**：New → Database → PostgreSQL（Railway 自動生 `DATABASE_URL`）
3. **加 App**：New → GitHub Repo → 選 `ai_os`（自動用 Dockerfile 建置）
4. App 的 Variables 填：
   | 變數 | 填什麼 |
   |---|---|
   | `DATABASE_URL` | 點「Add Reference」引用 Postgres 服務（值會是 `${{ Postgres.DATABASE_URL }}`） |
   | `APP_URL` | 部署完成後 Railway 給的網址（例 `https://xxx.up.railway.app`） |
   | `FAL_KEY` | 【必填】fal.ai/dashboard/keys 的金鑰——全站一律真實生成（示範模式已移除） |
   | `SEED_ADMIN_EMAIL` | 可不填——程式內建預設總管理員 `aa0968111723@gmail.com` |
   | `SEED_ADMIN_PASSWORD` | 可不填——已有內建預設密碼；**上線穩定後請設此變數換新密碼** |
   | `MCP_API_KEY` | **正式站不要設定**。舊共用超管金鑰只供本機／CI，production 會忽略；每位成員改在「接上外部 AI」專區自建個人金鑰 |
5. **建資料表**：用同一映像的 release／one-off job 明確執行
   `npm run db:migrate:dry-run && npm run db:migrate && npm run db:check`；成功後才啟動 Web。
   既有未納管 DB 先依 `docs/資料庫遷移.md` 做 dry-run 與 fingerprint baseline。
6. **自我診斷**：瀏覽器開 `你的網址/api/ready` —— 顯示「資料庫已接通」才算好；
   顯示錯誤就照畫面上的提示做（多半是 DATABASE_URL 沒用 Add Reference 引用 Postgres）
7. 開網址 → 用第 4 步的帳密登入 → 完成 ✅

> **忘記密碼／登入壞掉的萬能自救**：把 Variables 的 `SEED_ADMIN_EMAIL`＋`SEED_ADMIN_PASSWORD`
> 設成你要的帳密 → 按 Redeploy → 用新帳密登入。就算資料庫已有舊帳號也有效，完全不用碰資料庫。

## 四、日常使用（給宗祐團隊的說明）

**你（開發者）第一次做的事**：登入 → 右上「團隊管理」→ 邀請宗祐（勾剪輯組＋組長）→ 把邀請連結用 LINE 傳給他。之後宗祐自己邀組員。

**組員日常**：登入 → 建專案（選 Shorts 會自動直式）→ 填世界觀 3 題（可請 AI 導演給 idea）→ 生成 → 滿意的按「＋加入分鏡」→ 排順序 → 「送審」→ 等組長通過 → 「打包下載交付包」→ 進剪映剪

**組長日常**：分鏡出現「待審」→ 按 ✓ 通過或 ↩ 退回（附一句理由，會自動通知）；「團隊管理」可調每人每週點數額度（空=不限）

**所有人**：頂欄「回饋」按鈕 → 兩分鐘填七項 → 你在管理頁看彙整

**挑模型**：生成台先選「創作類別」（11 類：文生圖/圖生圖/文生影片/影片轉影片/LLM/圖轉文/語音轉文字/文字轉語音/文字轉音頻/訓練/工作流）再選模型（🏆旗艦/⚖️經濟/💡最低成本）；不知道選哪個 → 頂欄「模型指南」或 docs/模型目錄.md

**部署後健檢**：`你的網址/api/ready`（資料庫接通？）→ 登入 → 團隊管理「跑系統自檢」（七項全 ✅ 才算就緒）

## 五、點數怎麼運作（不鎖死）

- 1 點 ≈ NT$1 參考值；圖像 1–2 點、影片 5 秒 8–12 點
- 初始值：總預算 5000、每人每週 300——**只是初始值**，你隨時在「團隊管理→點數與額度」改
- 層級：個人覆寫 → 組設定 → 全域預設；**空白＝不限**
- 先扣預估、失敗全額退回，帳本可查

## 六、API 與 MCP（給之後接東西用）

- **API**：全部在 `/api/trpc/*`（tRPC，型別安全）；健康檢查 `GET /api/health`；交付包 `GET /api/export/:projectId`
- **MCP**：`POST /api/mcp`（JSON-RPC，header `x-api-key`）。**每位成員在「接上外部 AI」專區（頂欄選單）自建個人金鑰**，連進來就是「他本人」的身分與權限——只看得到自己有份的組與專案、扣自己的點數額度、一樣受審批門檻限制。金鑰可設**唯讀**（只准查詢）或**到期日**、可隨時撤銷；專區還有一鍵複製客戶端設定、測試連線、工具一覽與近期活動。
  - **工具（23 個，含細部連結各子系統）**：
    - 讀取：`whoami`／`list_projects`／`get_project_context`／`get_project_status`（一次取回分鏡＋生成＋代理＋排程＋待辦）／`find_model`／`list_generations`／`get_generation`（取回成品的免登入簽名網址）／`list_assets`／`list_databases`／`query_database`／`list_database_files`／`read_database_file`／`list_agent_runs`／`get_agent_run`／`list_schedule`
    - 寫入（唯讀金鑰一律擋）：`submit_generation`／`post_message`／`add_database_row`／`plan_agent`（請 AI 代理排多步計畫）／`approve_agent`／`stop_agent`／`discard_agent`／`add_schedule_item`
  - 例：在 Claude 說「看看《走出低谷》現在的狀況，規劃把知識庫腳本拆成分鏡並逐鏡出圖，順便排一個下週五的交付死線」——AI 會 `get_project_status → plan_agent → approve_agent → add_schedule_item`，全程以你的身分、走你的額度與審批門檻。
  - 權限與併發全走既有守門：MCP 的代理／排程／生成都重用網頁端同一套 core（`agentCore`／`scheduleCore`／`generationCore`），不分岔。正式環境只接受可撤銷、可到期、綁定個人的連線金鑰；舊 `MCP_API_KEY` 僅限本機／CI。
