# AI Director OS 技術債清償路線圖

> 目的：把目前已知的技術債轉成可執行、可驗收、可分批合併的工作，避免以一次大型重構影響正式環境。
>
> 原則：先處理資料安全與可復原性，再處理維護成本；每一階段都必須能獨立部署、獨立回滾。

## 現況判定

目前系統已具備 migration-first、後端與前端測試、E2E、非 root 容器、分散式限流、request ID、readiness 與背景 runner 管理，可視為成熟 Beta／準正式營運系統。

尚未完成的主要技術債分為五類：

1. 資料隔離：PostgreSQL RLS 尚未成為第二道防線。
2. 正式營運證據：監控、告警、備份與還原演練尚未形成可稽核證據。
3. 稽核生命週期：Audit retention 尚未定義並自動執行。
4. 供應商契約：CI 主要使用 mock，缺少真實 Fal.ai 低成本 smoke。
5. 可維護性：`server/index.ts` 過度集中，`storage.ts`、`points.ts` 仍需依責任拆分。

## 優先順序

### P0：資料安全與可復原性

#### 1. PostgreSQL RLS 第一階段

優先資料：

- 私訊與附件
- 自訂資料庫、資料列與文件
- 專案、素材與生成紀錄
- 團隊／組別資料
- 點數帳本的讀取範圍

驗收條件：

- 每個 request／background task 都能設定明確的 actor、team、group context。
- 無 context 的應用角色預設不能讀取租戶資料。
- RLS 與既有應用層 ACL 同時生效。
- 有跨租戶負向測試，包含 tRPC、REST、MCP、Agent、Workflow 與 Runner。
- migration 可由舊資料庫安全升級，且 rollback 採 forward-fix 或 restore，不依賴 destructive down migration。

#### 2. 正式監控與告警接線

必須觀測：

- `/api/health`、`/api/ready`
- HTTP 5xx、p95／p99 延遲
- DB pool、慢查詢、鎖等待
- generation／workflow／agent／export 最老工作與失敗率
- 點數退款失敗
- DB／Volume 容量
- Fal／NVIDIA／Google provider smoke

驗收條件：

- 告警至少有主要與備援接收者。
- 一次測試告警可被接收並留下證據。
- 每次部署可由 build SHA 對應到服務版本。
- incident runbook 中列出的指標都可在實際監控平台查到。

#### 3. 備份與還原演練

驗收條件：

- PostgreSQL 與 `/data` Volume 可在同一時間邊界備份。
- 還原到新的隔離環境，不覆蓋正式環境。
- 還原後通過 `db:check`、readiness、核心 E2E。
- 隨機抽查至少 10 個素材的 DB reference 與檔案雜湊。
- 驗證登入、權限、點數帳本與生成狀態。
- 記錄實際 RPO、RTO、開始與完成時間、失敗步驟與證據連結。

### P1：治理與供應商可靠性

#### 4. Audit retention

採用 `standard`、`security`、`privileged`、`billing` 四類保存政策；詳細規格見 `docs/Audit資料保存政策.md`。

驗收條件：

- Audit event 有 `retentionClass` 與 `expiresAt`。
- 每日批次可封存或清除到期資料。
- 點數帳本不由一般 Audit 清除工作刪除。
- 刪除、封存與保留政策變更本身也留下稽核紀錄。
- 私訊本文、密碼、token、cookie、完整 request body 不進 Audit metadata。

#### 5. 真實 Fal.ai smoke test

詳細規格見 `docs/真實供應商Smoke測試.md`。

驗收條件：

- 使用專用低額度帳號或 API key。
- 至少驗證一個低成本文字或圖片端點。
- 驗證 queue submit、poll、完成狀態、下載、MIME、檔案大小與持久化。
- 失敗不自動無限重試，不得造成不可控花費。
- 發布前與排程測試的結果可保存並追蹤。

#### 6. CI artifacts 與失敗證據

本路線圖 PR 先落地：

- 前端 coverage 報告
- migration／rate-limit 測試 log
- E2E server log
- container inspect 證據

驗收條件：

- CI 成功或失敗都能保留必要 artifacts。
- 成功 artifacts 保存 14 天，失敗調查資料保存 30 天。
- artifacts 不含 secret、cookie、token、私訊本文或使用者上傳內容。

### P2：架構與維護成本

#### 7. 拆解 `server/index.ts`

詳細計畫見 `docs/核心模組拆解計畫.md`。

目標：

- `index.ts` 僅負責 bootstrap、listen 與 process lifecycle。
- HTTP app 可在測試中建立而不 listen。
- Assets、exports、MCP、REST v1、health、middleware 各自有 route module。
- Runner 啟停由 lifecycle／bootstrap 統一管理。

#### 8. 拆解 `storage.ts`

目標責任：

- MIME／signature validation
- local volume adapter
- signed URL／asset access
- temporary file lifecycle
- storage health probe

驗收條件：

- 上層服務不直接依賴本機路徑。
- 可用 interface 替換 S3／R2／MinIO adapter。
- 路徑 traversal、MIME mismatch、磁碟滿載、簽名失效均有測試。

#### 9. 拆解 `points.ts`

目標責任：

- quota policy
- usage query
- reservation／capture／refund
- immutable ledger
- settings administration

驗收條件：

- 所有扣點只能經過單一 reservation／settlement API。
- refund、capture 與外部任務 callback 都具冪等鍵。
- 餘額與 ledger 在同一交易內一致。
- 併發扣點、重複退款、跨組污染、台北日／週界均有測試。

### P3：專案衛生與企業化

#### 10. 清理過期 PR 與分支

- 已被 default 取代：標記 `superseded` 並關閉。
- 仍有價值但落後：標記 `needs-rebase`。
- 純文件：標記 `documentation-only`。
- 不再適用：標記 `obsolete`。

#### 11. 安全供應鏈

後續加入：

- secret scanning
- SAST
- dependency review
- container vulnerability scan
- SBOM
- 產物簽章與 provenance

#### 12. 企業登入與治理

在內部使用規模擴大後評估：

- OIDC／SSO
- SCIM 或人員生命週期管理
- API key 定期輪替
- 稽核匯出與不可變封存
- 資料刪除／保留政策與法務確認

## 合併策略

不得把 P0～P3 全部做成單一 runtime PR。建議拆成以下獨立 PR：

1. CI artifacts 與文件基線。
2. Audit retention schema＋job。
3. 真實 provider smoke workflow。
4. RLS context foundation。
5. RLS 高敏感資料表第一批。
6. `server/index.ts` route extraction。
7. `storage.ts` adapter extraction。
8. `points.ts` quota／ledger extraction。
9. 正式監控與告警接線。
10. 備份還原演練證據。

每個 PR 都必須：

- 可獨立部署。
- 不改變無關產品行為。
- 有 migration／測試／觀測證據。
- 說明回滾或 forward-fix 方法。
- 更新本文件的完成狀態。

## 完成定義

當以下條件全部達成，可將系統標記為正式營運：

- [ ] RLS 第一階段覆蓋高敏感資料。
- [ ] 正式監控、告警與值班接收者已驗證。
- [ ] PostgreSQL＋Volume 還原演練成功。
- [ ] Audit retention 自動執行且有稽核紀錄。
- [ ] 真實 Fal.ai smoke 定期執行。
- [ ] CI 保存 coverage、migration、E2E 與 container 證據。
- [ ] `server/index.ts` 僅保留 bootstrap／lifecycle。
- [ ] `storage.ts` 與 `points.ts` 的高風險責任完成拆分。
- [ ] 過期 PR／分支完成清理。
- [ ] SLO 指標有實際數據，不只存在於文件。
