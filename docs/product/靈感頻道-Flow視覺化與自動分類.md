# 靈感頻道：Flow 視覺化、上傳分享、自動細化分類

> 對應程式：`shared/inspirationTaxonomy.ts`、`server/services/communityTaxonomy.ts`、
> `server/routers/community.ts`、`client/src/features/inspiration/*`、
> `client/src/styles.inspiration.css`、`drizzle/0040_community_taxonomy.sql`

## 這一版要解決的三件事

改版前的靈感頻道是一排等寬的小卡：72px 縮圖、標題、`Show Prompt` 按鈕、五格 mediaKind 篩選。
問題不在美醜，在於三個功能性缺口：

1. **看不到作品。** 72px 縮圖旁邊全是文字控制項，掃視一頁得到的資訊是「有幾則貼文」，
   而不是「有什麼作品」。這個頻道的價值是視覺參考，介面卻把視覺壓成配角。
2. **上不了架。** 唯一入口是「先進專案 → 找到提示詞庫／生成紀錄 → 按發布」。
   對「我手上就有一張圖想分享」的情境太遠，遠到沒人會走。
3. **找不到東西。** 五格 mediaKind 在貼文破百之後等於沒有篩選——
   使用者想找的是「夜景霓虹的城市空拍」，不是「圖片」。

## 一、Flow 視覺化

### 深色舞台

全站主色是暖象牙紙（`--bg #f3f0e8`）。素材縮圖貼在紙上時，每張圖的白邊都會跟背景打架，
眼睛先看到的是卡片邊框而不是作品。作法是把牆放進一塊**局部深色舞台**（`.flow-stage`）：

- 深色只在 `.flow-stage` 內生效（局部 CSS 變數），不動全站主題，也不需要 dark mode 基礎建設。
- class 一律 `flow-*` 前綴，與 `styles.css` 既有規則零碰撞；要移除整支拿掉即可。

### masonry 而非等高格線

用 CSS `columns` 而不是 grid：每張圖的長寬比不同，grid 只能靠裁切對齊，
而裁切會把「作者選的構圖」切掉——這面牆展示的正是構圖。

### prompt 壓在畫面上

`.flow-tile__scrim` 是這一版的核心：滑鼠移入淡入、觸控裝置常駐。
把 prompt 藏進詳情頁會讓「偷看別人怎麼寫」這個唯一價值歸零，所以
`FlowTile.test.tsx` 直接把它寫成契約——有人為了版面整潔拿掉字幕層，測試就會紅。

純文字貼文（提示詞、設定卡）不會變成一排灰盒子：由貼文 id 推出穩定色相
（`hueFromId`）生成專屬底色，掃視時仍能辨識。文字卡的字幕用 `.flow-tile__caption`
（正常流）而非 `.flow-tile__scrim`（絕對定位）——後者會與卡面引文疊字，是實際渲染驗證抓到的。

### 清單檢視保留

低頻寬與偏好純文字的人仍可切清單。兩種檢視共用同一個細節浮層（`FlowLightbox`），
動作只有一份實作，不會兩邊行為分岔。

## 二、上傳與分享

### 上傳直發

頻道頁的「上傳發布」把既有管線串成一頁：選專案 → `/api/upload` → `community.publishFromSource`。

**素材一定要落在某個專案**：權限、配額、儲存空間、回收桶全都掛在專案上，
繞過它等於開一條沒有 ACL 的儲存路徑。所以這裡不是新的上傳管線，
而是重用 `/api/upload` 連同它的組隔離、檢視者擋寫、MIME 檔頭簽名驗證與磁碟配額檢查。

素材本身沒有 prompt／模型欄位，但作者手上常常有（在別的工具生的圖）。
`publishFromSource` 因此接受 `promptText`／`modelId`——**只對 `sourceType=asset` 生效**。
提示詞與生成紀錄的 prompt 是系統快照的事實，不開放用貼文覆寫，
否則「Show Prompt」會與實際生成用的內容不符。

### 分享

分享連結是 `/community?post=<id>`，進站後自動打開那一則。
`navigator.share` 優先（手機一步轉進 LINE），退回複製連結；使用者關掉系統面板算成功，不跳錯誤。

**刻意不做免登入公開頁。** 全庫唯一的免登入內容出口是 `server/routers/share.ts`，
那份檔案的存在理由就是「審查對外公開了什麼只要讀一頁」。
靈感頻道是全站共用（站內），不是對外發表，在這裡開第二個公開出口會把那個保證作廢。

### 重新上架

`community.republish`（hidden → published）。沒有這支的話「下架」是單向門：
作者要把貼文放回頻道只能回原專案重發，而重發會換一個 id——
所有分享出去的連結、讚數與再用次數全部歸零。

## 三、自動細化分類

### 為什麼是字典而不是模型

1. 發布是同步動作，等一次模型回應要 1～3 秒，且要花點數；
2. 同一段 prompt 兩次分類結果可能不同，篩選面就不可信；
3. 分類規則要能被測試斷言——字典是資料，模型不是。

所以 `classifyInspiration()` 是**純函式 + 中英雙語關鍵詞字典**：
零延遲、零成本、可重現、可測。之後若要接模型，正確作法是模型只補作者標籤 `tags`，不覆寫 `autoTags`。

### 多面向而非單一樹

一張圖同時可以是題材＝城市、風格＝賽博龐克、氛圍＝孤獨、光線＝霓虹、鏡頭＝空拍。
單一分類樹逼人二選一，facet 不會。七個面向：

| facet | 說明 | 每則上限 |
| --- | --- | --- |
| `modality` 形式 | 由 mediaKind 推導，永遠有值 | 1 |
| `subject` 題材 | 人物／城市／自然／動物／食物／物件／載具／抽象／文字／科幻 | 2 |
| `style` 風格 | 寫實／動畫／插畫／水墨／3D／賽博／復古／極簡／像素／拼貼 | 2 |
| `mood` 氛圍 | 溫暖／寧靜／孤獨／史詩／黑暗／歡快／神秘 | 2 |
| `light` 光線色調 | 夜景／黃昏／霓虹／柔光／高對比／黑白／冷暖調 | 2 |
| `shot` 鏡頭視角 | 特寫／中景／廣角／空拍／仰角／主觀 | 2 |
| `usage` 用途 | 弘法禪修／海報／角色設定／分鏡／片頭／社群／配樂 | 2 |

標籤格式一律 `facet:value`（例 `subject:city`），存進 `community_posts.auto_tags`（jsonb + GIN 索引），
以 `@>` 做篩選。作者手寫的 `tags` 是另一欄——重算分類**只覆寫 autoTags**，人寫的字永遠不被機器蓋掉。

比對規則：含 CJK 的關鍵詞走子字串比對；純拉丁詞走字界比對，
避免 `ink` 命中 `thinking`、`3d` 命中 `a3db`。同一 facet 內關鍵詞不得重複
（重複會讓兩個值同分、排序只剩宣告順序＝分類形同擲骰），這條由測試守住。

### 字典升級不必停機

`TAXONOMY_VERSION` 落後的列在**被讀到時就地重算並寫回**（`healInspirationTaxonomy`）。
理由很實際：每次補關鍵詞都要「先跑一支 backfill 才敢部署」的話，
分類就會停在第一版不再改進——這是所有規則式分類真正死掉的原因。
沒人看的舊貼文永遠不會被算到，本來也不需要。

回寫是 best-effort（失敗只記 log，不讓 feed 掛掉），而且**不動 `updated_at`**——
重新分類不是作者編輯，不該把貼文推上「剛更新」。

要整站立刻對齊（例如篩選面必須完整）時跑：

```bash
npm run community:reclassify              # 只補版本落後的列
npm run community:reclassify -- --all     # 全部重算
npm run community:reclassify -- --dry-run # 只印會改什麼
```

### 篩選列的兩個細節

- **多選是 AND 不是 OR。** 選了「城市」再選「夜景」要收斂到兩者皆是的貼文；
  聯集會讓每多選一個條件結果就變多，跟使用者按下去的意圖完全相反。
- **chip 一定帶數量，且跟著目前條件收斂。** 沒有數字時使用者只能一個個點開才知道哪些是空的，
  點到空結果幾次就再也不會用篩選；數字若是全站總數而非 drill-down，點下去同樣是空的。

## 資料庫

`drizzle/0040_community_taxonomy.sql`，三欄兩索引，全部 `IF NOT EXISTS`（重跑無害）：

| 欄位 | 型別 | 用途 |
| --- | --- | --- |
| `auto_tags` | `jsonb` not null default `[]` | 字典產出的 `facet:value` 陣列，GIN 索引供 `@>` |
| `category` | `text` | 主分類（`auto_tags` 之一），卡片一眼看出「這是什麼」 |
| `taxonomy_version` | `integer` not null default 0 | 落後就重算；0＝從未分類 |

主分類挑選順序：題材 > 用途 > 風格 > 氛圍 > 光線 > 鏡頭 > 形式。
`modality` 一定有值，所以每則貼文至少有一個可篩選的標籤，篩選面不會出現破口。
