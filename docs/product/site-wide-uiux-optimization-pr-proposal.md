# 全站 UI/UX 優化計畫 PR 提案

> 狀態：Proposed  
> 適用範圍：Aios（AI 創作作業系統）全站前台體驗  
> 目標：讓第一次使用的人 30 分鐘內完成「一件看得懂的成果」，並在一週內把 Aios 變成**團隊日常創作作業場所**；介面更**視覺化、直覺**，文案更**中性、彈性**，並與 **Logo 色帶 × 沉靜弘法（monastic-calm）** 設計語言一致。

---

## 1. 背景與為何現在做

### 1.1 產品定位

Aios 是團隊向的 AI 創作作業系統：專案脈絡（世界觀／角色／場景／知識／資料）、創作（問 AI／生成／範本／計畫）、治理（點數／核准／權限）、交付（分鏡／打包）同一套流程。

目標使用者不限單一內容類型；介面與文案應支援多種創作場景，避免綁死特定語境。

### 1.2 現況問題（使用者視角）

| 層面 | 現象 | 後果 |
|------|------|------|
| **第一次** | 受邀進活躍組時導覽門檻常落空；長頁＋多入口並行 | 不知道下一步、不敢按 |
| **日常** | 待核／待辦主要藏在專案內；組長漏看 | 組員卡住、信任崩壞 |
| **認知** | 術語偏技術或偏特定敘事（如「咒語」「定盤星」） | 門檻高、彈性差 |
| **視覺** | Logo 多色絲帶 vs 介面偏單調說明牆 | 品牌感弱、掃讀困難 |
| **一致** | 扣點確認、權限唯讀、空狀態品質不均 | 「有時安全有時踩雷」 |
| **手機** | 長頁、FAB、多卡並存 | 主流程完成率低 |

### 1.3 與既有工作的關係

| 文件／工作 | 關係 |
|------------|------|
| [AI 創作工作台整合提案](./ai-creation-workbench-integration-pr-proposal.md)（PR #157 → WB-00～WB-06） | **工作台 IA 收斂**；本計畫假設工作台成為 ② 幕唯一 AI 主入口，並在其上做全站體驗升級 |
| `client/src/styles.css` monastic-calm tokens | **設計系統地基**；本計畫擴充語意色與元件樣式，不推翻 tokens |
| `client/src/brand.ts` + `/brand/*` | **Logo 資產唯一來源**；UI 一律走 `BrandLogo` |
| `docs/UX審查報告.md` | 高嚴重度項（待核可見、FirstRun 門檻、扣點確認一致、viewer 事前唯讀）納入 **UX-00／UX-01** 必做 |

本提案**不替代**工作台功能 PR，而是提供**全站體驗骨架 + 分階段實作切分**，避免各頁各自改文案、各自發明色票。

## 2. 北極星與成功指標

### 2.1 北極星

> **第一次進來的人，30 分鐘內完成一件可分享的創作成果；  
> 一週內，組員習慣每天打開 Aios 看待辦、創作、留言、審核；  
> 一個月後，團隊把「作業台 + 專案工作台」當開會與交付的固定場所。**

### 2.2 可量測（前端可觀測／質性）

| 指標 | 目標方向 |
|------|----------|
| 首次成功 | 範例專案或真專案「生成完成」或「分鏡有一格」 |
| 導覽覆蓋 | 受邀新人 per-user 看得到 FirstRun／輕量歡迎 |
| 待核 SLA | 組長從頂欄／首頁 1 點進待核，無需進每個專案翻 |
| 扣點安全感 | 所有扣點路徑有確認＋預估點數 |
| 掃讀 | 關鍵頁首屏主 CTA ≤ 1；模式選擇以圖＋短標為主 |
| 文案 | 使用者可見字串無「咒語」等黑話；placeholder 中性 |
| 手機 | 360px 完成：開專案 → 工作台一模式 → 生成確認 → 看結果 |

## 3. 設計原則（全站強制）

### P1 — 一條線，不是一排工具

- 作業台 → 專案三幕（①脈絡 → ②工作台 → ③交付）是主線。  
- ② 幕只有一個 **AI 創作工作台**；提示詞／生成紀錄／軌跡進資源區，不平行長卡。

### P2 — 5 秒知道按哪裡

- 每個畫面回答：我在哪？下一步？會不會扣點／要等人？  
- 主 CTA 用赤陶 solid；次要用 ghost／chip。

### P3 — 視覺優先於說明牆

- 狀態用 **色＋icon＋短標**（pill／chip），長文收進 Help 或二次展開。  
- 模式、步驟、空狀態以圖示卡為主，hint 一句話。

### P4 — 文案中性、彈性、可掃讀

- 面向「任何團隊創作」，不預設單一宗教／產業隱喻於 UI 正文。  
- 短句、動詞開頭、避免黑話與過長括號說明。  
- 組織角色可用產品既有名（組長／組員），但**權限提示**用使用者聽得懂的話（檢視／可編輯／需審核）。

### P5 — 一顆主色發聲 × Logo 色帶語意

- 頁面：暖灰地 + 象牙卡（既有 tokens）。  
- **同時只允許一顆飽和主 CTA 色（赤陶）**。  
- Logo 多色只作**語意映射**（見 §4），禁止彩虹大色塊導覽。

### P6 — 信任即留存

- 扣點必確認；viewer 事前 disable；草稿不丟；帶入不扣點；背景任務可追蹤。

### P7 — 手機與可及性一等公民

- 觸控 ≥ 40px；tablist 鍵盤；focus trap；`aria-live` 報成本／完成／錯誤；`prefers-reduced-motion`。

## 4. 品牌與視覺系統

### 4.1 Logo 色帶 → 產品語意（克制使用）

| Logo 區段 | 色感 | Token 對應 | 用途 |
|-----------|------|------------|------|
| A 紅→橙 | 啟動 | `--primary*` | 主 CTA、focus、選中 tab、主卡左邊條 |
| i 金→黃 | 注意／金錢 | `--gold*` | 估點、待核、queued、新手步驟 |
| o 綠 | 進行／完成 | `--success*` | done、步驟完成、可交付 |
| s 青藍 | 協作／系統 | **新增** `--collab*`（soft／ink／rgb） | 執行軌跡、組動態、協作狀態（非主 CTA） |

**禁止**：四模式 tab 四種實心底、長頁彩虹分區、用 soft 當正文色。

### 4.2 Logo 合法出場

| 場合 | 用法 |
|------|------|
| Splash／登入／邀請 | full color wordmark（hero） |
| 頂欄 | mark 或 sm full |
| 空狀態 | 低飽和絲帶線稿或 mark + 一句話 |
| 列印／匯出 | light 底 + full logo |

元件一律 `BrandLogo` + `brand.ts`，禁止硬編路徑。

### 4.3 建議新增／統一的視覺元件

| 元件 | 用途 |
|------|------|
| `.creation-mode-tab` | 四模式大卡：icon 區 + 短標 + 極淡 tone border |
| `.first-run-steps` | 新手步驟橫向／換行視覺列 |
| `.rhythm-bar` | 作業台「今日節奏」：待核／執行中／未讀 |
| `.status-pill` 語意擴充 | collab 態（軌跡／同步中） |
| `.quick-chips` | 短啟動 chip（問 AI 建議句、篩選） |
| 統一 empty-state | 標題一句 + 主次 CTA + 可選圖示 |

## 5. 文案系統（中性・彈性）

### 5.1 用語對照（全站替換表）

| 避免（使用者可見） | 改用 |
|--------------------|------|
| 咒語 | 提示詞 |
| 定盤／定盤星 | 已設定／專案基調 |
| 生成台（對使用者） | 直接生成／工作台 |
| 過長技術括號 | 收進 Help 或次級 hint |
| 強綁特定場景的 placeholder | 中性場景描述（光、空間、節奏） |

內部 code comment 可保留歷史語境；**UI 字串與 Help 正文**走中性表。

### 5.2 語氣

- **短**：主標 ≤ 12 字；hint ≤ 一句。  
- **中性**：不預設使用者身分（法師／工程師…）。  
- **彈性**：「可選」「需要時」「依設定」取代絕對語氣。  
- **誠實**：扣點、核准、唯讀一定講清楚。

### 5.3 空狀態公式

```text
[發生什麼事]  →  [為什麼常見]  →  [一個主行動]  +  [一個次行動]
例：尚無提示詞 → 成功生成後會自動出現 → 前往直接生成 → 使用說明
```

## 6. 全站資訊架構與畫面清單

### 6.1 全域殼

| 區域 | 優化重點 |
|------|----------|
| Splash | Logo 儀式；無功能列表 |
| 頂欄 | 品牌 mark、組別、點數、**待核 N**、帳號；sticky |
| 導覽 | 作業台／專案內 Toc 三幕；少而穩 |
| 回饋 FAB | 不遮生成／核准／抽屜主按鈕 |
| Help | 用語與四模式、扣點承諾對齊 |

### 6.2 到達與身分

- Login、Accept invite、權限錯誤頁：清楚「你是誰、進哪組、能做什麼」。

### 6.3 作業台 Launchpad

- **今日節奏**（待核／執行中／未讀）  
- **繼續上次專案**  
- 專案卡角標（待核金、執行中綠）  
- **Per-user FirstRun**（非「整組零專案」）  
- 搜尋／篩選視覺工具列  

### 6.4 專案頁

- ① 脈絡：世界觀／角色／場景／知識／資料（進階可收）  
- ② **唯一** CreationWorkbench  
- ③ 分鏡・審核・打包・留言  
- 角色橫幅（檢視者事前唯讀）  
- 「從這裡開始」四步視覺化，完成可收  

### 6.5 AI 創作工作台

- 目標一句 + 四模式視覺 tab  
- 上下文 chip 跳轉  
- 資源抽屜：提示詞／生成／軌跡  
- 成本摘要元件全模式一致  
- 帶入不送出、不扣點  

### 6.6 其他高流量頁

| 頁 | 優化 |
|----|------|
| 資料庫 | 空狀態、匯入主路徑視覺化 |
| 排程／筆記 | 草稿保存、離開提醒（UX 審查） |
| 模型指南 | 卡片掃讀、少術語 |
| 成員／點數 | 表格清晰、危險操作確認 |
| 整合／MCP | 進階預設收合 |
| Chat／訊息 | 空狀態、未讀一致 |

## 7. 使用者旅程（設計交付物）

### 7.1 第一次（受邀新人）

```text
邀請連結 → 登入/接受 → 作業台（per-user 歡迎）
  → 開範例（不扣點）或開新專案
  → ① 寫一句基調 → ② 工作台直接生成 → 確認點數
  → 看結果 → 可加入分鏡
  = 第一次成功
```

### 7.2 日常組員

```text
打開 Aios → 繼續上次／今日節奏 → 工作台
  → 生成或問 AI → 留言 → 下班看是否待核
```

### 7.3 日常組長

```text
頂欄待核 → 核准 → 看執行中 → 必要時調權限/點數
```

### 7.4 週會

```text
同一專案 → ③ 分鏡狀態 pill → 對進度 → 打包交付
```

## 8. 分階段 PR 拆分（建議 DAG）

> 原則：**先信任與導流，再視覺與文案系統，再各頁打磨**；每 PR 可獨立測、可回退。  
> 與 WB stack：若 WB-01～06 尚未合併，UX-02 起以工作台為準；UX-00／01 可與 WB 並行。

### UX-00：體驗基線與字串盤點（不改視覺）

- 盤點全站使用者可見字串（頁面／元件／Help）。  
- 建立替換表（§5.1）與禁止清單。  
- 截圖／關鍵流程清單：登入、邀請、作業台、專案三幕、生成確認、待核、交付。  
- 補齊／標註既有 client 測試覆蓋缺口。  
- **不改 UI 行為**（或僅加 data-testid）。

**依賴**：無  

**驗收**：字串清單 + 流程清單合入 docs；CI 測試綠。

---

### UX-01：信任與導流（高嚴重度修復）

- Per-user FirstRun／輕量歡迎（修「活躍組新人零引導」）。  
- 頂欄 + 作業台專案卡 **待核／待辦** 可見與深鏈。  
- **全站扣點確認一致**（含分鏡格生成／配音）。  
- Viewer／唯讀 **事前** disable + 常駐說明。  
- 生成／確認文案與 CostSummary 對齊。

**依賴**：UX-00（可部分 overlap）  
**驗收**：UX 審查高嚴重度項可勾選關閉；關鍵路徑 e2e 或 component 測。

## 11. 非目標

- 不重寫後端生成／點數／權限核心。  
- 不在本計畫導入全新設計系統套件（維持 CSS tokens）。  
- 不做無限畫布／節點編輯器。  
- 不強制 Dark mode（可列未來）。  
- 不一次改完所有歷史 seed 文案（可分批）。  
- 不把 Logo 四色做成全站主題色狂歡。

## 13. 第一個實作 PR 的嚴格範圍
