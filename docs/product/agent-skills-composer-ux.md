## 1. 為什麼要重做入口

我們後端能力強（規劃、DAG、扣點、定裝對齊），但介面像「四個產品 + 工程狀態機」：

- 問 AI／直接生成／製作範本／執行計畫＝要先學分類  
- `agent_run`、估點、規劃模型、稽核軌跡＝代碼感  
- 職能寫在說明裡，用起來卻要繞「問 AI」才排得出計畫  

創作者的心智是：**一句話 → 誰來做 → 看畫面進度 → 過目開拍**，不是先選 runtime。

---

## 2. 競品研究（創作者產品，2024–2026）

| 產品 | 創作者怎麼用 | 我們可借 | 不要抄 |
|------|--------------|----------|--------|
| **Runway** | 單一生成 session；底部選模型；用「鏡頭／畫面」語言 | 主舞台乾淨、少分頁；用分鏡語彙 | 不要求先讀工程術語 |
| **Adobe Firefly Assistant** | **一個對話**指揮多步（PS／Premiere／Firefly） | 「你下目標，系統編排」；少切上下文 | 不做成假帳號員工 |
| **Firefly Boards** | 視覺思考牆：靈感 → 迭代 | 技能／職能用**卡面**不是列表 API | 不做無限畫布 NLE |
| **CapCut** | 範本大圖、風格 chip、點一下就預覽感 | 技能＝可點的**畫面卡**；一鍵帶入 | 不堆設定 |
| **Midjourney** | 結果格子先於文字狀態 | 進度旁將來可接縮圖（後續） | 不走 Discord 複雜度 |
| **Grok 多代理／工具** | 主輸入 + **＋** 掛工具；chip 可卸 | **＋ 技能**掛劇組；多代理是**敘事** | 不引入 multi-agent mesh |

共同點：

1. **一個主輸入框**當舞台中心  
2. **能力是外掛／卡面**，不是平行四個 App  
3. **畫面語言**（鏡頭、風格、角色）勝過系統語言（run、token、mode）  
4. **進階藏起來**（模型、用量、稽核）  

---

## 3. 產品定錨（給創作者）

> **寫你想完成的畫面或片子。**  
> **＋ 請誰來幫忙（分鏡、出圖、配音…）。**  
> **你過目後才開拍；關頁也會繼續做。**

後端仍是：一句 goal →（可選）技能偏好 → plan／generate → 核准 → `agent_run` + Command 扣點。  
**多代理是劇組心智，不是多套 runtime。**

---

## 4. 畫面感規則（反代碼式）

| 不要 | 要 |
|------|-----|
| `role.storyboard`、mode=plan | 「分鏡助理」「多步計畫」 |
| 待核准 awaiting_approval | **待你過目**／**可以開拍** |
| 規劃模型／tokens 預設全開 | 收在「進階」 |
| 長說明牆 | 卡面：圖示 + 一句人話 + 點一下 |
| 四 tab 搶主視覺 | 主：輸入；次：＋技能；tab 降為捷徑 |
| 稽核軌跡當首屏 | 步驟清單用圖示狀態；軌跡收合 |

視覺：

- 技能卡：**圓形圖示底 + 暖色調性**（對齊 monastic-calm）  
- 已選技能：可卸的 **pill chip**（像標籤貼紙）  
- 待過目列：**醒目橫幅 + 主按鈕「開拍」**

## 5. 分階段

### Phase 1（本分支）— 入口變好用、有畫面感

- [x] 技能目錄（模式 + 職能）  
- [x] 目標旁 **＋ 技能** 視覺選單（卡面，非代碼列表）  
- [x] 選技能 → 切能力／補目標提示  
- [x] 執行計畫可**直接排步驟**  
- [x] 待過目**置頂開拍**  
- [x] 文案去工程化  

### Phase 2 — L2 劇組席位

- 本專案啟用哪些職能、一鍵「請分鏡助理」  
- 職能週點上限（人話：「這週分鏡預算」）  

### Phase 3 — 閉環更像組員

- CA-05 回報／檢查點（「拍完一段請你看」）  
- 步驟旁縮圖（生成完成即見畫面）
