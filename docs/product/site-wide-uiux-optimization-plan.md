## 0. 文件目的

本文件為 **Aios 全站 UI/UX 優化的正式規格與執行計畫**，供產品、設計與工程共同執行。

**涵蓋：**

1. 從「第一次使用」到「團隊日常創作」的體驗目標  
2. **手機版、平板版、桌面版** 的版面、導覽、觸控與密度規格  
3. Logo 色帶 × monastic-calm 品牌視覺規則  
4. 中性、彈性的全站文案準則  
5. UX-00～UX-08 可獨立審查、測試、回退的 PR 切分  
6. 分裝置驗收標準與非目標  

**不涵蓋：** 後端生成引擎重寫、新資料模型、無限畫布類編輯器。

## 1. 執行摘要

### 1.1 問題

| 維度 | 現況 | 影響 |
|------|------|------|
| 第一次使用 | 受邀進活躍組常無導覽；長頁多入口 | 不知道下一步 |
| 日常團隊 | 待核／待辦不易跨專案看見 | 組長漏審、組員卡住 |
| 文案 | 部分黑話或過長說明（如「咒語」「定盤星」） | 門檻高、適用面窄 |
| 視覺 | Logo 多色 vs 介面說明牆 | 掃讀差、品牌弱 |
| **手機** | 長頁、FAB 遮擋、多卡並存、觸控目標偏小 | 主流程完成率低 |
| **桌面** | 寬螢幕資訊密度不均；頂欄與長頁協作弱 | 專業感與效率不足 |
| 一致 | 扣點確認、唯讀權限表現不一 | 信任成本高 |

### 1.2 目標（正式）

| 時程 | 目標 |
|------|------|
| **首次 30 分鐘** | 完成一件可分享成果（範例或真專案生成／分鏡） |
| **一週內** | 組員習慣每日開啟：待辦、創作、留言、審核 |
| **一個月內** | 作業台 + 專案工作台成為開會與交付固定場所 |
| **全裝置** | 同一資訊架構；**手機可完成主流程，桌面可高密度協作** |

### 1.3 成功指標

| 指標 | 手機 | 桌面 |
|------|------|------|
| 首次成功 | 360px 完成生成確認並看到結果 | 同上，且可並排看上下文 |
| 待核可見 | 頂欄或底欄 1 點進入 | 頂欄常駐待核數 |
| 扣點安全 | 所有扣點有確認＋預估 | 同左 |
| 主 CTA | 首屏可見、≥44px 觸控 | 清晰層級、鍵盤可達 |
| 文案 | 無黑話；hint ≤ 一句 | 同左；Help 對齊 |
| 無橫向溢出 | 360／390 必過 | 1280／1440 可讀密度 |

## 2. 裝置策略（正式）

Aios 採 **同一套產品、三套呈現密度**，不是三個產品。

### 2.1 斷點定義（與現況 CSS 對齊並正規化）

| 名稱 | 寬度 | 代號 | 對應現況 |
|------|------|------|----------|
| **手機 Phone** | ≤ 560px | `S` | `@media (max-width: 560px)` |
| **平板 Tablet** | 561px – 820px | `M` | `@media (max-width: 820px)` 區間 |
| **桌面 Desktop** | ≥ 821px | `L` | 預設；內容欄 max-width 1180px |
| **寬桌面 Wide** | ≥ 1200px | `XL` | Launchpad 網格加密等 |

**驗收基準裝置（必測）：**

| 類型 | 基準 |
|------|------|
| 手機窄 | **360 × 800** CSS px |
| 手機常見 | **390 × 844** |
| 平板直 | **768 × 1024** |
| 桌面 | **1280 × 800** |
| 寬桌面 | **1440 × 900** |

### 2.2 裝置原則

| 原則 | 說明 |
|------|------|
| **Mobile primary for completion** | 主創作路徑（開專案 → 工作台 → 生成 → 看結果 → 待核）必須在 S 可完成 |
| **Desktop primary for density** | 桌面強化多欄、對照、長列表、鍵盤與多任務，不強迫手機塞同樣密度 |
| **No feature exile** | 不得「僅桌面才有生成／核准」；進階管理可在 S 改為摺疊，但路徑存在 |
| **Touch first sizes** | 可點目標 **≥ 44×44px**（S/M）；桌面可 36px 次要，主 CTA 仍 ≥ 40px |
| **Safe area** | PWA standalone：`env(safe-area-inset-*)`；底欄／FAB 避開 Home Indicator |
| **Input zoom** | iOS：表單字級 ≥ 16px 或等效，避免 focus 強制縮放破壞版面 |
| **One hand** | S：主 CTA 與模式切換優先在拇指熱區（中下半屏）；少依賴 hover |

### 2.3 導覽模型（分裝置）

#### 手機（S）

```text
┌─────────────────────────────┐
│ 頂欄精簡：Mark · 組 · 待核 · 我 │  sticky
├─────────────────────────────┤
│                             │
│     主內容（單欄）             │
│                             │
├─────────────────────────────┤
│ 底欄（可選 P1）：作業台｜專案｜待辦 │  或僅用頂欄+Toc
└─────────────────────────────┘
  FAB 回饋：右下，上移避開會／生成鈕
```

- 專案內：**三幕 Toc** 可為底部橫滑 chips 或精簡 sticky 次列（①②③），**不**把四模式都做成整頁章節。  
- 工作台模式：**2×2 網格** 或 **橫滑 segmented tabs**；同時只展開一個面板。  
- 資源：底部 sheet（全寬、max-height ~85vh）。

#### 平板（M）

- 單欄為主；Launchpad 卡 2 列。  
- 頂欄可顯示較完整組名；模式 tab 可 4 列並排。  
- 彈窗置中，寬度 max 480–560px。

#### 桌面（L／XL）

```text
┌─ 頂欄：Logo · 組別 · 點數 · 待核 · 導覽 · 帳號 ─────────────┐
│  .app max-width 1180 (XL 可維持，避免無限拉寬段落)            │
│  ┌─ 主欄 ──────────────────────────────────────────────┐   │
│  │ 三幕長頁；工作台主卡；必要時右側不強制第二欄（先求穩定）   │   │
│  └────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────┘
```

- 頂欄完整；組別選擇器 min-width 充足。  
- Launchpad：自動填網格；XL 間距加大。  
- 鍵盤：模式 tab 方向鍵、抽屜 Esc、主操作 focus 環可見。  
- Hover 僅增強，**不**作為唯一操作手段。

### 2.4 版面密度

| 元素 | 手機 S | 平板 M | 桌面 L+ |
|------|--------|--------|---------|
| 頁面左右 padding | 12–16px | 16–20px | 20px |
| 卡片 padding | 14–16px | 16–20px | 20–24px |
| 主卡 `card--primary` | 略減 padding | 標準 | 標準／略增 |
| 字級正文 | 15–16px | 15px | 15px |
| 網格專案卡 | 2 列 | auto-fill ~180+ | auto-fill ~240+ |
| 模式 tab | 2×2 或橫滑 | 4 欄 | 4 欄 |
| 說明文字 | 預設更短；詳見可摺 | 短 | 可稍詳但仍忌牆 |

### 2.5 關鍵元件分裝置行為

| 元件 | 手機 | 桌面 |
|------|------|------|
| **頂欄** | 單列精簡；溢出進選單 | 完整工具 |
| **待核** | 角標數字必見 | 數字 + 可展開列表 |
| **Launchpad 卡** | 2 列、封面矮 | 較大封面、更多 meta |
| **FirstRun** | 步驟可換行網格；主 CTA 全寬 | 橫向步驟 + 並排按鈕 |
| **工作台模式** | 大觸控塊 + 短標 | 同結構、可略扁 |
| **生成確認** | 底部 sheet 或全寬 modal | 置中 modal |
| **資源抽屜** | 底部 sheet + 焦點陷阱 | 同或右側 drawer（P2） |
| **TocNav** | 橫滑 chips／底列 | 側或頂部輕量 |
| **分鏡列表** | 單欄卡片 | 可較密列表 |
| **資料表** | 橫向滾動 + 凍結首欄（若需要） | 全表 |
| **回饋 FAB** | 避開底欄與主 CTA | 右下固定 |

### 2.6 手勢與系統 UI

| 項目 | 規格 |
|------|------|
| 下拉重新整理 | 不與內部 scroll 衝突；長列表以按鈕「重新整理」備援 |
| 返回 | 瀏覽器返回不應丟草稿（creationDraft／local draft） |
| 軟鍵盤 | 固定底欄／FAB 在 keyboard 開啟時上移或暫隱（P1） |
| 橫向手機 | 不保證最佳；至少無裁切主 CTA、可捲動完成 |
| reduced-motion | 取消非必要滑動與脈衝動畫 |

### 2.7 PWA／安裝

| 項目 | 手機 | 桌面 |
|------|------|------|
| 安裝提示 | InstallAppBanner；iOS 指引 | 可安裝則提示 |
| standalone | safe-area；底 padding | 視窗控制列 drag 區已有則保留 |
| 離線 | offline.html 中性文案 | 同左 |

## 3. 北極星與原則

### 3.1 北極星句

> 第一次進來的人，在 **手機或桌面** 都能於 30 分鐘內完成一件成果；  
> 團隊把 Aios 當 **每日創作與審核的作業系統**，而不是偶而打開的工具頁。

### 3.2 強制原則

| ID | 原則 | 摘要 |
|----|------|------|
| P1 | 一條線 | 作業台 → 三幕；② 僅一工作台 |
| P2 | 5 秒行動 | 我在哪／下一步／扣點或等待？ |
| P3 | 視覺優先 | 色 + icon + 短標；少說明牆 |
| P4 | 文案中性彈性 | 短句、無黑話、跨內容類型可用 |
| P5 | 一主色發聲 | 赤陶 CTA；金／綠／collab 僅語意 |
| P6 | 信任 | 扣點確認、唯讀事前、草稿不丟、帶入不扣點 |
| P7 | 雙端一等 | 手機可完成；桌面可高效；功能不放逐 |

## 4. 品牌與視覺（正式）

### 4.1 Logo 色帶語意

| Logo | 語意 | Token | 使用 |
|------|------|-------|------|
| A 紅橙 | 啟動 | `--primary*` | 主 CTA、focus、選中、主卡左邊條 |
| i 金 | 注意／成本 | `--gold*` | 估點、待核、queued、新手 |
| o 綠 | 完成／健康 | `--success*` | done、可交付、步驟完成 |
| s 青 | 協作／系統 | `--collab*`（新增） | 軌跡、組動態、協作中 |

**禁止：** 彩虹導覽、多實心色主按鈕並排、`--soft` 當正文。

### 4.2 Logo 出場

| 場合 | 手機 | 桌面 |
|------|------|------|
| Splash | full，寬度 ≤ 72vw | full hero |
| 登入／邀請 | full 置中 | full 置中或左品牌欄（可選） |
| 頂欄 | mark 優先 | mark 或 sm full |
| 空狀態 | mark + 一句 | 同左 |

一律 `BrandLogo` + `brand.ts`。

### 4.3 建議元件 class

- `.creation-mode-tab`（含 `--ask|generate|template|plan` tone）  
- `.first-run-steps` / `.first-run-step`  
- `.rhythm-bar`（今日節奏）  
- `.quick-chips`  
- `.app-bottom-nav`（手機底欄，若採用）  
- 統一 `.empty-state`

## 5. 文案系統（正式）

### 5.1 替換表

| 避免（使用者可見） | 使用 |
|--------------------|------|
| 咒語 | 提示詞 |
| 定盤／定盤星 | 已設定／專案基調 |
| 生成台（對使用者） | 直接生成／工作台 |
| 過長技術括號 | Help 或次級 hint |
| 強綁特定場景 placeholder | 中性光影／空間／節奏描述 |

### 5.2 語氣

- 主標短、hint 一句、動詞清楚  
- 不預設使用者行業或信仰語境  
- 扣點／核准／唯讀必須明示  

### 5.3 空狀態公式

`現況 → 常見原因（可省）→ 主行動 → 次行動`

## 7. 分裝置：關鍵流程規格

### 7.1 第一次成功（手機）

1. 邀請 → 登入 → 作業台（per-user 歡迎全寬主 CTA）  
2. 開範例（不扣點）或新建  
3. ① 一句基調（大輸入、少欄位）  
4. ② 點「直接生成」大 tab → 提示詞 → 生成（確認 sheet）  
5. 結果在資源／列表可見  

**通過條件：** 360px 無橫向溢出；主按鈕不被 FAB 遮住；確認可完成。

### 7.2 第一次成功（桌面）

同流程；確認為置中 modal；可同時看到上下文摘要 chip。

### 7.3 組長待核（手機）

頂欄待核角標 → 列表 → 進入專案核准區（深鏈展開）。  

### 7.4 組長待核（桌面）

頂欄「待核 N」→ 下拉或頁面列表 → 新分頁或同頁深鏈。  

### 7.5 日常創作（手機）

繼續上次 → 工作台 → 單模式編輯 → 抽屜看結果。  

### 7.6 日常創作（桌面）

繼續上次 → 工作台；可快速切模式；列表密度較高。

## 9. 驗收標準（正式簽核用）

### 9.1 產品

- [ ] ② 幕僅一 AI 工作台主入口  
- [ ] 作業台可完成：繼續創作、看待核、開新案  
- [ ] 首次路徑有 per-user 引導或範例  

### 9.2 信任

- [ ] 所有扣點有確認與預估  
- [ ] Viewer 事前唯讀

## 18. 首頁與主要使用流程分析

基於實際巡覽與 `homepage-record.md` 的紀錄，目前首頁與主要使用流程的分析如下：

### 18.1 首頁 (Login Page) 體驗分析
- **極簡專注**：採用 `100dvh` 滿版置中佈局，無全域導覽列與外部干擾連結，確保使用者專注於「登入」單一目標。

- **防呆與提示**：明確標示「帳號採邀請制」，並在輸入錯誤時提供友善的本地端與伺服器端錯誤提示（如 Email 格式檢查）。

### 18.2 主要使用流程 (Main User Flow)
1. **到達與登入**：使用者透過邀請連結到達首頁，完成登入。
2. **進入作業台 (Launchpad)**：登入後首站，呈現「今日節奏」、「繼續上次」與「專案網格」，提供快速進入工作狀態的入口。
3. **專案創作 (Project Workspace)**：進入特定專案後，透過「三幕導覽」與「四模式工作台」進行 AI 生成與編輯。
4. **審核與交付**：生成結果透過資源抽屜或列表呈現，並與頂欄的「待核」通知連動，完成團隊協作閉環。

## 19. 桌面版、平板版及手機版問題

基於 UX-00 基準盤點與各裝置尺寸的實際截圖，目前全站存在以下跨裝置的 UI/UX 問題，將於後續 UX-01 至 UX-08 階段逐步修復：

### 19.1 桌面版 (L-1280, XL-1440) 問題
- **資訊密度不均**：寬螢幕下部分卡片與表單過度拉伸，缺乏有效的多欄佈局或最大寬度限制，導致閱讀視線過長。
- **導覽與長頁協作弱**：專案工作台等長頁面缺乏穩定的側邊或頂部錨點導覽（TocNav），使用者在深層捲動時容易迷失上下文。
- **鍵盤與多任務支援不足**：部分互動元件（如自訂下拉選單、彈窗）缺乏明確的 focus 狀態，且未完全支援鍵盤操作（如 Esc 關閉、方向鍵切換）。

### 19.2 平板版 (M-768) 問題
- **過渡態佈局尷尬**：部分網格（如 Launchpad 專案卡）在 768px 時未能平滑過渡，可能出現單列過寬或三列過擠的情況。
- **彈窗與浮層比例**：部分 Modal 或 Sheet 在平板直向模式下佔據過大比例，未適當限制最大寬度（max-width），導致視覺壓迫感。

### 19.3 手機版 (S-360, S-390) 問題
- **觸控目標過小**：部分次要按鈕、連結或選單項目的點擊區域小於 44×44px，不符合行動裝置的觸控標準。
- **元件遮擋與溢出**：右下角的 FAB（浮動操作按鈕）容易遮擋底部內容或主 CTA；部分資料表或長字串未妥善處理，導致頁面出現橫向捲動（水平溢出）。
- **長頁面缺乏收納**：手機端將所有模式與內容堆疊成單一長頁，缺乏有效的摺疊（Accordion）或橫滑分頁（Tabs）機制，導致主流程完成率低。
- **安全區域 (Safe Area) 遺漏**：部分頁面底欄未避開 iOS Home Indicator，導致誤觸。

## 20. P0、P1、P2、P3 問題清單

根據 UX-00 基準盤點與跨裝置測試結果，將目前發現的 UI/UX 問題依嚴重程度與修復優先級（P0 ~ P3）整理如下：

### P0：核心流程阻斷與嚴重體驗缺陷（必須立即修復）
- **[手機]** 360px 窄螢幕下存在水平溢出（橫向捲動），破壞版面整體性。
- **[手機]** 右下角 FAB（浮動操作按鈕）在特定長度下會永久遮擋底部的「主 CTA 按鈕」，導致無法進行下一步。
- **[雙端]** 扣點操作缺乏明確的二次確認與預估，容易造成使用者誤觸扣點（信任危機）。
- **[PWA]** 獨立應用程式模式（Standalone）下，底欄未避開 iOS Home Indicator（缺乏 `safe-area-inset-bottom`），導致按鈕難以點擊。

### P1：重要功能體驗不佳（強烈建議於 UX-01~UX-03 修復）
- **[桌面]** 專案工作台等長頁面缺乏穩定的側邊或頂部錨點導覽（TocNav），深層捲動時容易迷失。
- **[手機]** 觸控目標過小，部分次要按鈕與選單項目點擊區域小於 44×44px。
- **[雙端]** 待核項目（審核通知）在跨專案時不易被發現，導致組長漏審、組員卡住。
- **[平板]** Launchpad 專案卡網格在 768px 斷點時過渡不平滑，佈局顯得尷尬。

### P2：次要頁面與進階互動問題（安排於 UX-04~UX-07 修復）
- **[桌面]** 寬螢幕（1440px+）下，部分表單與卡片缺乏最大寬度限制，資訊密度過於稀疏。
- **[雙端]** 資料表（Databases）與排程（Planner）在手機端缺乏有效的橫向滾動或卡片化收納策略。
- **[無障礙]** 鍵盤操作支援不完整，部分自訂下拉選單與彈窗缺乏明確的 focus 狀態與 Esc 關閉支援。
- **[平板]** 彈窗（Modal）與底部抽屜（Sheet）在直向模式下佔據比例過大。

### P3：視覺打磨與微調（安排於 UX-08 或後續版本）
- **[視覺]** 部分空狀態（Empty State）缺乏引導性文案與次要行動按鈕。
- **[文案]** 系統內仍殘留少部分技術黑話（如「定盤星」），需全面替換為中性文案。
- **[動效]** 頁面切換與彈窗出現的過場動畫可進一步優化，並確保完全支援 `prefers-reduced-motion`。

- **手機端 FAB 與底欄衝突**：右下角的回饋/操作 FAB 容易與系統底欄 (或 PWA Home Indicator) 發生空間衝突，需在 UX-02 實作避讓機制。
- **Sticky 導覽列衝突**：手機端若同時啟用頂欄 (Topbar) 與章節導覽 (TocNav) 的 `sticky` 定位，會佔用過多垂直可視空間，目前已規劃將手機端頂欄改為 `static` 以解決此衝突。
- **手勢衝突**：手機端瀏覽器的「下拉重新整理」可能與長列表或畫布的內部捲動產生手勢衝突，需透過 CSS `overscroll-behavior` 或 JS 攔截處理。

## 23. 全站導覽重整方案

為解決目前全站導覽在跨裝置時的擁擠與層級不清問題，提出以下導覽重整方案（將於 UX-02 與 UX-04 階段實作）：

### 23.1 導覽層級定義
- **L1 全域導覽 (Global)**：跨專案、跨群組的系統級操作（如：切換群組、個人帳號設定、全域通知/待核、回到作業台）。
- **L2 區域導覽 (Local)**：特定專案或工具內的模組切換（如：專案內的三幕切換、資料庫的分頁）。
- **L3 內容導覽 (Contextual)**：單一長頁面內的錨點跳轉（如：專案工作台內的章節跳轉）。

### 23.2 桌面版導覽重整 (L-1280, XL-1440)
- **頂欄 (Topbar)**：專注於 L1 全域導覽。左側固定為 Logo 與回到作業台，中央為群組切換與全域搜尋，右側為待核通知、點數與個人帳號選單。
- **側邊欄 (Sidebar / TocNav)**：專注於 L2 與 L3 導覽。在專案工作台等長頁面中，左側或右側提供固定的章節導覽列，支援滾動監聽（Scrollspy）與快速跳轉。

### 23.3 手機版導覽重整 (S-360, S-390)
- **精簡頂欄 (Mobile Topbar)**：僅保留最核心的 L1 功能（Logo/返回、群組簡稱、通知小紅點、漢堡選單）。取消 `sticky` 定位以釋放垂直螢幕空間。
- **底部導覽或橫滑標籤 (Bottom Nav / Scrollable Tabs)**：
  - **作業台**：可考慮引入底部導覽列（首頁、待辦、個人），或維持單頁上下滾動。
  - **專案內**：L2/L3 導覽改為頂部橫滑標籤（Scrollable Tabs）或底部懸浮操作列（Bottom Sheet/Chips），確保單手操作的便利性，並避免與系統 Home Indicator 衝突。
- **選單收納**：將次要的全域操作（如：說明中心、設定）收納至全螢幕的漢堡選單或個人帳號抽屜中。
