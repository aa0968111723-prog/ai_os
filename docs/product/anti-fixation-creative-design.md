## 1. 問題

AI 輔助發想若一次給出**單一、完整、像標準答案**的產出，容易誘發 **design / creative fixation**：

> 無意識地把探索鎖在先例（含自己的第一念與 AI 成品）上，還以為自己在「選最好的」。

經典定義（Jansson & Smith, 1991）：設計過程中盲目、有時適得其反地固守一組有限想法。  
生成式 AI 研究另見：完整 AI 圖／文可造成固著或 fixation displacement；複雜任務上 LLM 可經固著路徑降低創意表現；限制輸出形態有助緩解。

本文件**不重述全部文獻**，只把可驗證的設計約束寫死，供「陪你做完」「一起想」與工作台主路徑對照實作。

---

## 2. 設計目標

| 目標 | 可觀察標準 |
|------|------------|
| 降空白焦慮 | 沒靈感入口不靠「你想做什麼？」冷啟動 |
| 抗單一錨定 | 關鍵決策步至少 **2～3 個短選項**，禁止預設唯一完整企劃 |
| 中等協助 | AI 提議、人確認後才寫入／扣點（既有 Confirm + runAction） |
| 可丟棄第一錨 | UI 明確支援「換方向／略過／之後再改」 |
| 產物在場 | 對話旁可見 logline／分鏡／有圖數，避免空轉聊天 |

### 非目標

- 禁止所有範例（範例可靈感；害在**完整度與單一性**）  
- 全自動一鍵成片  
- 改 quota／generation 計價契約

## 3. 核心原則（必須遵守）

### P1 — 劑量：中等協助（倒 U）

- 協助太少 → 過載、空白頁。  
- 協助太多 → 被動、自動化偏誤、固著。  
- **預設**：選項 + 一句複述 + 確認；不預設「已幫你做完整支」。

### P2 — 輸出形狀：短、多、可丟

| 禁止（易固著） | 要求（反固著） |
|----------------|----------------|
| 單一長文完整企劃當唯一答案 | 每輪 **2～3** 個方向 chip（標題 + ≤1 句） |
| 「最佳／推薦唯一」口吻 | 「可先試 A，之後可換」 |
| 未確認就寫入專案或出圖 | 確認後才 `runAction`／generate |
| 一輪同時定調+拆鏡+出圖 | **一次只推進一個產物**（對齊 #404 phase） |

### P3 — 時機

- **沒靈感路徑**（陪你做完）：允許先出 3 方向（跳板），但**必須選或改寫**才能進下一 phase。  
- **已有一句話路徑**：提供「我先寫 → 再請 AI 擴」，對齊「先獨立再 LLM」較利自主感。  
- 禁止：進入共創後**立即**倒出整份分鏡+提示詞+生成佇列。

### P4 — 換框優先於精修

固著時死磕同一提示詞無效；提供明確換框：

- 換受眾／場合  
- 換調性（溫柔／莊嚴／日常…）  
- 換結構（3 鏡／4 鏡／先旁白後畫面）  
- 「先隨便一個，之後再改」合法 CTA  

### P5 — 醞釀與可中斷

- 允許退出共創、稍後回來；phase 與伺服器資料一致。  
- 不強迫連續聊完四段；進度條可點跳（進階）但不跳過確認門檻。

### P6 — 擁有感

- 寫入前複述：「我將把一句話故事設成…」  
- 所有扣點動作維持 ConfirmButton。  
- 檢視者唯讀；不可在共創殼繞過權限。

## 4. 套用面（實作對照表）

### 4.1 陪你做完（#404）

| Phase | 反固著要求 |
|-------|------------|
| **theme** | 開場 3 主題方向；禁止空問「想拍什麼」；選後複述再 `apply_worldview_chips`／logline |
| **structure** | 給 3／4／6 鏡或「貼腳本」；禁止一次生成帶完整 shot list 長文且自動寫入 |
| **visuals** | 每鏡短提示詞建議；主 CTA「生成這一格」；可「換提示／跳過」；顯示估點 |
| **wrap** | 缺格提示；送審仍確認；不自動連發 |

### 4.2 一起想（ProjectAssistant）

| 項目 | 要求 |
|------|------|
| 冷啟動快捷句 | 保留「3 個 idea」類；避免單一「幫我做完整支片」為唯一主按鈕 |
| actions | 繼續多顆可選；生成可換模型；帶入工作台不扣點 |
| 長回答 | 若含完整方案，UI 仍拆成可執行 actions，避免只有牆文 |

### 4.3 工作台主路徑（#400）

- 共創／簡易進行中：**預設收合** AI 理解、消融、進階追蹤，避免與「選項 + 一顆主 CTA」搶注意力。  
- 空狀態優先露出「沒靈感？陪你做完」與簡易入口，而非進階面板。

### 4.4 定裝／上下文（#402）

- 從共創進定裝再返回：恢復 phase，不強制重跑 theme 完整 AI 答案。  
- 定裝卡是**可編輯錨點**，不是不可改的 AI 聖旨。

## 5. 文案與 UI 模式（可直接實作）

### 5.1 開場（theme）

```
標題：沒靈感時，先選一個方向（之後都能改）
[方向 A 標題 — 一句]
[方向 B 標題 — 一句]
[方向 C 標題 — 一句]
[我自己打一句話故事]
```

### 5.2 複述確認

```
將把專案定成：「…」
調性：…
[確認寫入] [換一個] [我改字]
```

### 5.3 階段頂部提示（固定）

```
這一步只會幫你定下《一句話故事》，不會直接出圖。
```

（structure／visuals 各換對應一句，防止期待一次做完。）

### 5.4 反模式文案（禁止）

- 「已為你生成完整專案方案如下」（後接不可選長文）  
- 「最佳分鏡是…」作為唯一路徑  
- 未標點數的「一鍵全部生成」

## 6. 終端機 checklist（與 #404 對齊）

```
[ ] D1  陪你做完 theme：3 chip + 自填；無「你想做什麼」唯一開場

[ ] D5  visuals 逐格或明確批量確認；估點可見
[ ] D6  「換方向／先隨便／之後再改」在 theme、structure 可見
[ ] D7  共創進行中收工進階面板（對齊 #400 主路徑）
[ ] D8  自動化測試：phase 完成條件不依賴 LLM 全文（純資料推導）
[ ] D9  手動：選 A 後可換 B 再寫入；取消確認不落庫、不扣點
```

建議在實作 #404 G0–G2 的 feat PR 描述中勾選本表 D1–D9。

---

## 7. 測試要點

1. **固著壓力測試**：theme 只給 1 個超完整方案 vs 3 短 chip——後者為合格設計。  
2. **取消路徑**：任何 Confirm 取消後 DB 與點數不變。  
3. **換框**：寫入 logline 後可再進 theme 修改並覆寫（權限內）。  
4. **空轉**：僅聊天不按確認 → 摘要區仍顯示「尚未定調」。

## 8. 文獻錨點（實作不需展開）

- Jansson & Smith (1991)：design fixation 定義與範例效應  
- 範例 meta：範例可降多樣性、有時升新穎；少而罕見範例較利  
- Incubation / forgetting-fixation：誤導線索需被弱化  
- GenAI：完整產出易固著；constrained 輸出有助；先獨立再 AI 利自主  
- 倒 U：中等 AI 協助較佳  

細節見對話研究整理；**衝突時以本文件 P1–P6 與 checklist 為準**。
