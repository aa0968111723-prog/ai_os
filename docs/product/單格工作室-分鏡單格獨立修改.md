# 單格工作室：分鏡單格獨立修改、版本與多模型修正

> 需求出處：PR #187 討論——「單分鏡獨立畫面修改，希望能夠像 Adobe 那樣能夠單圖獨立拉出來修正，
> 還有版本、編輯與不同模型修正等等，希望能深度整合」。
> #187 只做到「分鏡列可就地改提示詞＋重生這一格」；本文件描述的是把那一格真正**拉出來**修的完整流程。

## 一、解決什麼問題

改一格畫面之前只有一條路：改提示詞 → 重生 → 整張重畫。於是

- **構圖被洗掉**：只想換天色，結果人物站位、鏡位全變了。
- **改壞了回不去**：舊版只存在生成紀錄裡，得離開分鏡去翻。
- **只能用一種模型**：分鏡列的「逐格生成模型」只列文生圖，沒有任何「吃底圖」的修圖模型。

單格工作室把這三件事收進同一個全螢幕畫面，且**所有動作只影響這一格**。

## 二、三個動作

| 分頁 | 做什麼 | 送出的生成 |
|---|---|---|
| **修正這張** | 以現用畫面（或任一版）當底圖，只改指定的地方 | `scenes.refine` → 圖生圖／圖生影片（`needs: "image"`） |
| **重畫這格** | 換模型從頭重畫，構圖整個換掉 | `scenes.generateInto` → 文生圖／文生影片 |
| **版本** | 回看歷來每一版（模型／指示／點數／成敗），一鍵切回 | `scenes.setVisualFromAsset` |

「修正」是這次的核心：`generations.sourceUrl` / `sourceAssetId` 這條路徑本來就在（生成台的圖生圖用它），
只是分鏡從來沒接上。接上之後，模型目錄裡的重繪、局部修、放大、去背、轉場動態全部可以逐格套用。

## 三、版本模型：不新開表

**現用是哪一版的單一真相＝`scenes.assetId` / `scenes.narrationAssetId`**（兩個指標欄），
**歷來版本＝`generations` 裡 `scene_id` 綁到該格的每一列**。

指標欄結構上就保證「同一 (scene, role) 至多一個現用版本」——正是
`shared/animationContracts.ts` 的 AssetVersion 契約要用 uniqueness 檢查逼出的性質。
再開一張 `asset_versions` 表只會讓同一件事有兩個真相，且需要對帳，因此**本次沒有 schema 變更、沒有 migration**。

`shared/sceneVersions.ts` 是純投影：把「生成紀錄 ＋ 指標」算成使用者看得懂的清單。

- 版次（第 N 版）依「同 role 由舊到新」編號，**不會因為新生成而跳號**；`createdAt` 相同時用 id 決勝，版次穩定。
- 狀態：`current`（指標指到的）／`candidate`（可切回）／`generating`／`awaiting_approval`／`failed`。
- 點數以**淨消耗**計（實花減退回）——失敗全額退點的版本顯示 0 點，不會把退掉的點繼續算在人頭上。

### 版本可逆性

「＋加入分鏡」建立的格子，其來源生成原本 `scene_id` 是 null，不會出現在該格版本清單裡——
切到別版之後就再也切不回那張原圖。因此 `addFromGeneration` 現在會把來源生成**回綁**到新格
（僅在該生成尚未綁定任何格時），版本自此可逆。舊資料沒回綁的，仍以「外部帶入」列進清單
（`SceneExternalAsset`），並由 `setVisualFromAsset` 以素材 id 切回——它不需要生成紀錄。

## 四、深度整合的接點

| 面向 | 怎麼接 |
|---|---|
| 扣點／退點 | 全部走 `executeGenerationCommand` → `submitGenerationCore`：估點、成本審核門檻、`reserveQuota`、失敗自動退點，與生成台同一條路 |
| 專案 ACL | `getProjectChecked(..., forEdit)`：檢視者能回看版本與成本，寫入鈕一律不出現；後端同樣擋 |
| 專案狀態機 | `assertProjectNotArchived`：封存專案不接受付費生成 |
| 角色／場景卡 | 工作室的重生與修正都注入生成台勾選的同一套錨點，畫風不分岔 |
| 冪等 | `clientRequestId` 每格自持，成功才換新鍵——timeout 重按不重複扣點 |
| 併發防抖 | `assertNoPendingVisual`：同一格已有進行中的畫面生成就擋（重生與修正共用，配音獨立不互相鎖） |
| 回填 | 完成後由既有 `advanceGeneration` 回填該格 `assetId`，修完自動換上，舊版仍在清單 |
| 操作紀錄 | `scenes.refine`／`scenes.setVisualFromAsset` 已補進 `AUDIT_ACTION_LABELS` |

## 五、把錯誤擋在扣點之前

模型目錄 300+ 條，選錯一支就是白扣一次點。兩份判斷寫在 `shared/sceneVersions.ts`，**前後端共用**：

- `isSceneRegenModel`＝不需來源、輸出畫面 → 「重畫這格」的清單與後端守門
- `isSceneRefineModel`＝吃圖片來源、輸出畫面 → 「修正這張」的清單與後端守門

因此不會出現「前端給了按鈕、後端拒收」。此外 `generateInto` 現在會明確擋下需要底圖的模型，
訊息直接指路到單格工作室，而不是等送到 provider 層才回一句看不懂的「此模型需要來源」。

底圖本身也逐條擋：不是本專案的、進了回收桶的、不是圖片的（影片／音訊版本），都在扣點前回中文訊息。

## 六、UI 要點

- 全螢幕 `role="dialog"` ＋ `useFocusTrap`（焦點鎖、鎖背景捲動、Esc 關閉、關閉後焦點還給開啟者）。
- 左舞台看畫面（可預覽任一版並「看回現用」），右工具改東西；≤900px 改單欄，舞台在上。
- **工作室掛在 `SceneList` 層級，不掛在分鏡列內**——`.gen-row` 帶 `content-visibility: auto`（paint
  containment），會成為 fixed 定位的包含區塊，modal 掛在列內會被裁掉。
- 有版本在跑時輪詢加快到 4 秒（有人正盯著等出圖），閒置 20 秒。
