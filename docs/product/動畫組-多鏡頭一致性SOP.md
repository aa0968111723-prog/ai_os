# 動畫組・多鏡頭一致性 SOP

> 給動畫組夥伴：怎麼用 Aios 讓「同一個角色／場景／道具／畫風」換了鏡頭還是同一個。
> 本文每一句「系統會怎樣」都對得上程式碼，並有一支可重跑的機器證明：
> `scripts/e2e-animation-consistency.py`（跑法見文末）。

## 動畫組的核心痛點

動畫最怕「連戲穿幫」：第 3 鏡的小蓮臉圓了一點、第 5 鏡的燈籠變成沒有流蘇、夜景忽然
變暖色。一致性不是「生成時多寫幾個字」就能保證的——**要有一個所有鏡頭共用的『聖經』，
而且每一鏡都自動、逐字地把同一份設定帶進生成**，改設計時還要知道「哪些舊鏡頭因此過時」。

Aios 把一致性拆成六層，動畫組只要把「聖經」建好，之後每一鏡都自動繼承。

## 一致性的六層（每一層都對應一種你會穿幫的地方）

| 你怕穿幫的東西 | 系統的鎖定機制 | 落地位置 | 生成時注入的錨點 |
|---|---|---|---|
| 故事背景・畫風・調性 | **世界觀**（logline／訊息／調性／視覺風格／禁語） | `projects.worldview`（`shared/worldview.ts`） | `[專案背景]` |
| 角色長相（身份） | **角色卡** 的 `appearance`（Identity，不變） | `characters`（`server/routers/characters.ts`） | `[角色定裝] 外觀鎖定 {角色}：…` |
| 角色造型（服裝，逐鏡可換） | **造型卡**（Look），逐鏡用 `lookIds` 綁 | `character_looks`（`characterLooks.*`） | 同句 `…，造型鎖定：{服裝}` |
| 場景（色板／光線） | **場景卡** `palette`＋`lighting` | `scene_presets`（`scenePresets.*`） | `[場景設定] 光影鎖定 {場景}：色板 …、光線 …` |
| 每個細節素材（道具） | **道具卡** `appearance`，可歸屬到角色／場景 | `props`（`props.*`） | `[素材設定] 材質鎖定 {主人的} {道具}：…` |
| 角色動作物理（走位／運鏡／動作） | 逐鏡 `action`＋`camera`＋`performance` | `scenes`（`scenes.update`） | 影片模型注入 `｜動作：…`＋`[鏡頭語言] …` |

組裝順序是固定的（`shared/promptSections.ts`）：**鏡頭指令 → `[專案背景]` → `[角色定裝]`
→ `[場景設定]` → `[素材設定]`**，由 `server/services/generationCore.ts`
的 `prepareGenerationRequest()` 統一組。你在生成台看到的預覽（「這次生成，AI 會怎麼理解」）
就是這一份，所見即所送。

### 上面這些不是說說而已——實際組出來長這樣

（節錄自機器證明的輸出，`fal-ai/wan…` 影片模型、假生成模式）

```
除夕入夜的老街，小蓮提著紅燈籠站在長長的青石板路起點，阿福蹲在她腳邊

[專案背景] 調性:溫暖(warm, gentle)、懷舊|視覺風格:2D 手繪動畫|故事錨點:…尋找回家的路。|核心訊息:再遠的路，只要有一盞燈，就找得到家。
[角色定裝] 外觀鎖定 小蓮：六歲女孩、圓臉、齊瀏海黑色短髮…；外觀鎖定 阿福：橘白色胖貓…、脖子繫一個小銅鈴
[場景設定] 光影鎖定 除夕老街：色板 暖橙與靛藍對比、青石板路…、光線 入夜燈籠暖光、遠處煙火冷光
[素材設定] 材質鎖定 小蓮的紅燈籠：紅紙燈籠、金色流蘇、深褐竹骨、正面墨字一個「福」…
```

## 兩個讓「多鏡頭」真的一致的關鍵設計

### 1. 一致性快照（fingerprint）：同一組卡片 = 同一個指紋

每次生成都會把「當下用的角色／場景／道具卡內容＋造型」凍成一份
`continuity_snapshot`，並算一個 SHA-256 `fingerprint`（`server/services/continuity.ts`）。

- **同一組卡片綁定的鏡頭，指紋逐字相同** → 這批鏡頭真的是同一份設定畫出來的。
  機器證明裡 6 個鏡頭的指紋都是 `40fccb97…`。
- **重試（retry）沿用快照**，不會因為別人中途改了卡片而悄悄換臉／換色。
- fingerprint **不含**逐鏡的鏡頭語言（鏡別／運鏡）——所以你「把中景改成特寫」不會被
  當成「換了一組卡片」，但仍會被連戲檢查標成畫面過時（見下）。

### 2. Identity 不變、Look 逐鏡換

角色的「臉／身形」放 `appearance`（Identity，整部片不變）；「這一鏡穿什麼」放造型卡
（Look），逐鏡用 `lookIds` 綁。除夕夜想讓小蓮換上大紅棉襖，只要那一鏡綁 `look_night`：

- 身份錨點不變（`外觀鎖定 小蓮：…圓臉…`），
- 造型錨點變成 `造型鎖定：大紅棉襖…`，
- **指紋刻意改變**（`b3ee96e2…` ≠ 日常的 `40fccb97…`）——因為那的確是另一個外觀狀態，
  系統要能區分，而不是假裝一致。

## 連戲檢查：不一致會「被通知」

`story.continuityCheck`（`server/services/continuityCheck.ts`）把每一鏡「現在顯示的圖」
回溯到它的快照，逐欄比對現在的卡片，回報哪些鏡頭過時、為什麼過時：

- 改了**某一鏡的動作**（角色動作物理）→ **只有那一鏡**過時，原因寫「動作」。
- 改了**角色外觀**（改角色設計）→ **所有用到那個角色的鏡頭全部**過時，原因寫「外觀」
  ——這就是設計改動的「爆炸半徑」，讓你一眼看到要重生哪些鏡，而不是等成片才發現。
- 只改**備註**（notes）不會過時（備註不進畫面）；改**配音／音效**也不會讓圖過時
  （刻意分開，見 `shared/continuity.ts` 的說明）。

## 動畫組標準流程（SOP）

1. **先立聖經（最重要）**：在專案裡把世界觀填好，建齊角色卡、場景卡、道具卡、造型卡。
   **每張卡盡量上一張定裝／概念參考圖**（`referenceAssetId`）——文字錨點鎖「描述」，
   參考圖才鎖「長相」（見下節「一致性的極限」）。
2. **故事 → 分鏡**：可以貼故事讓系統自動抽角色／場景／道具卡（story-first，
   見 `scripts/e2e-story.py`），或手動一鏡一鏡建（`scenes.addDraft`）。
3. **逐鏡綁卡＋定鏡**：每一鏡綁上這一鏡出現的角色／場景／道具（`scenes.setCards`），
   選這一鏡的造型（`lookIds`），填鏡頭語言（鏡別／運鏡／機位／焦段／構圖）、表演
   （情緒／視線）、動作（走位）。
4. **生成前先預覽**：打開「這次生成，AI 會怎麼理解」，確認 `[專案背景]`、每個角色的
   `外觀鎖定`、`光影鎖定`、`材質鎖定` 都在、參考圖有幾張被帶上。錨點缺了就是卡片沒綁到。
5. **生成 → 入庫 → 進分鏡**：成品自動入素材庫並回填到那一格。
6. **改設計時看連戲檢查**：改了角色外觀／場景色板／某鏡動作後，到連戲檢查看哪些鏡過時，
   逐一決定要不要花點數重生（系統永遠只提醒、不自動重生）。

## 要讓「三視圖」真的鎖住長相：選對模型（實測）

文字錨點鎖「描述」；要鎖「同一張臉」，得把角色卡的**定裝參考圖**（三視圖）真的餵進生成。
但**只有支援多圖參考（`image_urls`）的模型才會吃參考圖**。生成前預覽的
「參考圖 X/Y」就是在告訴你這次帶進去幾張（實測 `generation.preview`）：

| 模型 | 生成前預覽的「參考圖」 | 能不能鎖三視圖 |
|---|---|---|
| `fal-ai/nano-banana-2/edit`、`nano-banana-pro/edit` | 2/2 | ✅ 會帶進參考圖 |
| `fal-ai/bytedance/seedream/v4.5/edit` | 2/2 | ✅ |
| `fal-ai/qwen-image-edit-plus` | 2/2 | ✅ |
| `fal-ai/flux-pro/kontext/max`（單圖） | 0/2 | ✖ 只吃單一來源圖 |
| 純 `text-to-image` / `text-to-video`（flux schnell、wan、kling…） | 0/2 | ✖ 只有文字錨點弱鎖 |

**動畫實務兩段式**：① 用多圖 edit 模型（nano-banana / seedream / qwen-image-edit）＋三視圖
產「鎖好長相的關鍵影格」；② 再用 image-to-video（wan / kling 影生影）讓關鍵影格動起來。
最多帶 4 張參考圖（`applyContinuityReferences`）。

## 一致性的極限（誠實說明，避免動畫組誤會）

- **文字錨點保證「描述一致」，不保證「像素級同一張臉」。** 要更硬的鎖定，靠兩件事：
  （a）每張卡上**定裝參考圖**，且用**支援多圖參考**（`image_urls`）的模型——系統會把卡片
  參考圖自動帶進去（最多 4 張，`applyContinuityReferences`）；（b）同一顆 seed（若模型支援）。
- **角色動作物理**目前只在**影片模型**會注入提示詞（`｜動作：…`）；純靜態圖不把動作寫進
  提示詞（避免把「走路」畫成文字），但仍凍進快照供連戲檢查。要看到動作真的影響畫面，
  用 text-to-video／image-to-video 模型。
- **造型逐鏡換會讓指紋改變**——這是正確行為（不同外觀＝不同一致性狀態），不是 bug。
- 沒有 `FAL_KEY` 時是真實模式、生成會失敗退點；要免費把整條一致性流程測完，用假生成
  模式（`E2E_MOCK=1`）。

## 機器證明（可重跑）

`scripts/e2e-animation-consistency.py` 用「老街紅燈籠」6 鏡短片把上面每一條都驗一遍
（約 70 項斷言）：世界觀注入、角色／場景／道具錨點跨鏡逐字一致、造型鎖定、逐鏡動作物理、
跨鏡指紋一致、換造型指紋改變、連戲檢查對「改動作／改外觀」的過時判定，以及
**三視圖模型選擇**（純影片 `參考圖 0/N`＋`multi_reference_unsupported`；
`nano-banana-2/edit` 才 attached≥1）。

```bash
# 獨立庫（不動開發資料庫；第一次先 createdb）
sudo -u postgres createdb aios_anim_e2e
bash scripts/run-animation-consistency.sh
# 或走共用 e2e runner（會重置該次使用的 DB）
bash scripts/run-e2e-local.sh animation-consistency
```

輸出末端會印出「一鏡的完整組裝提示詞」、「跨鏡 continuity 指紋表」與「三視圖模型選擇對照」。
