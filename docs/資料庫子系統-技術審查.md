# 資料庫子系統技術審查（多代理 + 實機驗證）

> 方法：對整個資料庫子系統（約 3,100 行：`shared/{databaseFields,csv,tabular}.ts`、
> `server/routers/databases.ts`、`server/services/{databaseAcl,databaseCore,databaseFiles,restApi,storage}.ts`、
> `server/services/mcp.ts` 資料庫工具、`client/src/pages/DatabasesPage.tsx`）做多代理平行審查
> ＋上網對照 2024-2025 最佳實務，並在本機把 app 實際跑起來（Postgres + prod build + 瀏覽器登入 +
> tRPC/REST 邊界測試）逐項重現。四個面向：正確性/邊界、安全、效能/擴展、UX/相容。
>
> 結果：15 項經對抗驗證確認的問題 + 4 份上網研究。本 PR 修掉 5 項「解析層correctness/UX」與可安全落地者，
> 其餘較大或屬既有架構者列為建議追蹤。

## 實機驗證確認「有效的既有防護」（別誤修）

在跑起來的實例上打真實 payload，以下控制**確認有效**：

| 控制 | 驗證 |
|---|---|
| CSV 匯出公式注入中和 | 存 `=1+1`/`@SUM(A1)`/`=cmd` → 匯出成 `'=1+1`/`'@SUM(A1)`/`'=cmd` ✔ |
| ICS 行事曆換行跳脫 | 文字欄注入 `\r\nSUMMARY:HIJACK\r\nBEGIN:VALARM…` → 被跳脫成單行 `\n`，無 ICS 注入 ✔ |
| 列驗證（各匯入格式共用） | 不存在日期 `2026-02-30`、必填缺值、select 非選項值 → 皆正確擋下 ✔ |
| 5000 列匯入上限 | 6000 列 CSV → imported 5000 / skipped 1000 / truncated=true ✔ |
| 畸形輸入不炸 | 壞 JSON → 人話 BAD_REQUEST；JSON 內容誤傳 format=csv → 「沒有可匯入的資料列」不崩 ✔ |

## 本 PR 已修（5 項）

### 1.〔HIGH·正確性〕`parseDelimited` 欄位中途裸引號吞併整份剩餘 — `shared/csv.ts`
未加引號卻含裸引號的 CSV（英吋記號 `24" pipe`、內文引號）會讓解析器無條件切入引號模式，把後續的
分隔符/換行/整條列都併進同一格，**靜默資料錯位＋整列遺失且無錯誤回報**。
改為 RFC 4180 寬容解析：只有在「欄位開頭」（cell 為空）時 `"` 才是引號起點，欄位中途的 `"` 原樣保留。
實機重現：`24" pipe,10\r\n阿哲,20` 修前吃掉第二列、修後兩列都進、`24" pipe` 完整保存。

### 2.〔MEDIUM·UX/相容〕JSON 匯入不 trim，與 CSV/TSV 不一致 — `shared/tabular.ts`
分隔類每格 `.trim()`，JSON 不 trim。同一份資料 JSON 版的 `" done"`／`"2026-01-01 "` 會過不了
select/date 驗證、CSV 版卻通過（「換個格式就壞了」）。改為 JSON 攤平值也 `.trim()`。

### 3.〔MEDIUM·正確性〕重複表頭：預覽取首欄、匯入取末欄不一致 — `shared/csv.ts`
`parseTabular` 去重保留**第一欄**，`delimitedToRowObjects` 卻讓**最後一欄**覆寫。改為匯入端也「首欄優先」。

### 4.〔正確性〕number 欄位 `Number()` 太寬鬆把代碼型字串靜默變數字 — `shared/databaseFields.ts`
實機發現：`Number("0x10")===16`、`Number("0b10")===2`。匯入產品編號 `0x10` 會被靜默存成 16。
改為只收十進位寫法（正負號/小數/科學記號/前後空白），擋 `0x`/`0b`/`0o` 與千分位。

### 5.〔UX〕大量貼上同步全量解析凍結 UI — `client/src/pages/DatabasesPage.tsx`
`usePreview` 每次按鍵都同步 `parseTabular`（最多 1.5MB）。加 250ms 去抖，停手才解析一次。

## 建議追蹤（較大／既有架構，未在本 PR 動）

### 高優先

- **〔HIGH·效能〕匯入逐列串行 count+insert+updatedAt**（`databaseCore.ts` / `databases.ts` importData 迴圈）
  5000 列 ≈ 1.5 萬次串行 DB 往返（每列一次整表 `count(*)` + insert + `updatedAt` update），
  易拖垮/逾時單一請求。建議：進迴圈前算一次 count、以記憶體累加判斷保險絲；通過驗證的列**分批多值 insert**；
  `updatedAt` 整批結束後 update 一次。保留逐列驗證與部分成功語義。

- **〔HIGH·效能〕`linkedToProject` 整表載入再於 JS 過濾**（`databases.ts:237`）
  一次把所有含 project 欄位之可見庫的**全部列（含完整 jsonb）**撈進 Node 再 `filter`，無 SQL 條件/LIMIT/索引。
  最壞達 200 庫 × 20k 列。建議：把 `projectId` 比對下推 SQL（`data->>key = $id` 的 OR，配 GIN 索引）。
  另註：實際掃描範圍未依 `project.groupId` 收斂，與 docstring「只掃該組」不符（無跨界外洩，但範圍過寬）。

- **〔HIGH·安全〕SSRF 守門只驗字面 IP，主機名不做 DNS 解析**（`databaseFiles.ts:124`）
  攻擊者把自控網域 A record 指向 `169.254.169.254`（雲端 metadata）或內網 IP，`importUrl`/`refreshFile`
  即可抓內網回應並經 `textContent` 讀回（憑證/內部服務外洩）。非 rebinding，純靜態解析繞過。
  建議：連線前 `dns.lookup(host,{all:true})`，對每個解析 IP 套同一組私網/link-local/metadata 判斷，
  並把 socket pin 到已驗證 IP（消 rebinding 殘餘窗口），或改出口代理白名單。程式碼註解已自承此為已知限制。

- **〔HIGH·安全〕檔案抽取 DoS 與過時相依**（`databaseFiles.ts`；上網研究）
  `docx`（mammoth 解 zip）與 `pdf-parse@1.1.1`（內附舊 pdf.js，暴露 **CVE-2024-4367** 任意 JS 執行）
  於上傳請求內**同步、無逾時、無解壓大小上限**執行。建議：升級/替換 pdf 解析、加解壓後大小上限與逾時、
  重活動移出主事件迴圈（worker）。

- **〔HIGH·UX/相容〕硬性 UTF-8 解碼**（前端 `f.text()`、後端 `buf.toString("utf8")`；上網研究）
  介面全繁中，但 Windows Excel 另存的 Big5/UTF-16 CSV 會亂碼。建議：偵測 BOM/編碼或提供編碼選項。

### 中／低優先

- **〔MEDIUM·安全〕公式注入危險字元集不全**（`csv.ts`）：`/^[=+\-@\t\r]/` 缺 LF 與**全形 ＝＋－＠**（CJK 輸入法易產生）。
- **〔MEDIUM·安全〕REST 寫入接受 `?key=` 帶全權金鑰**（`restApi.ts`）：金鑰隨 URL 進 log/歷史易外洩；
  可對 POST 僅收 header、`?key=` 僅留給 ICS 訂閱（日曆 App 無法送 header）。
- **〔MEDIUM·UX〕從檔案建表一律推斷為 text 型別**（`tabular.ts inferFields`）：數字/日期/勾選型別遺失。
  建議：整欄皆數字→number、皆 ISO 日期→date 的輕量推斷。
- **〔MEDIUM·安全〕`docx`/`xlsx` 二進位誤判為 csv**（`detectFormat`）：歐系分號 CSV 亦整行當單欄。
- **〔LOW〕** `coerceBoolean` 單字母 `v`/`o` 語意含糊；`listRows` 的 `jsonb::text ILIKE '%q%'` 無法走索引且被 count 重跑；
  count-then-insert 非原子並發可略超上限；`listVisibleTables` 硬 `limit(200)` 靜默截斷無提示；
  offset 分頁排序鍵非唯一跨頁可能漏/重；MCP 只提供單列 `add_database_row`（無多格式匯入）。

## 上網研究來源（節選）

- OWASP WSTG — CSV Injection；Symfony 安全公告 GHSA-2xhg-w2g5-w95x（Excel 重存可復活已中和公式）。
- CVE-2024-4367（pdf.js < 4.2.67 任意 JS 執行）；decompression bomb 防護通則。
- SSRF 防護：DNS pinning／出口白名單／metadata 端點阻擋（169.254.169.254）。
- 匯入編碼：UTF-8 BOM 與 Big5/GBK 中文 CSV 偵測；型別/地區化解析陷阱。
