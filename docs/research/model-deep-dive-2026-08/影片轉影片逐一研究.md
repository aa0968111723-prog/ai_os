# 影片轉影片（V2V）逐一研究 #1–#3（2026-08）

> 來源：fal 官方 schema / llms.txt / OpenAPI 對照站內 `shared/models.ts` video-to-video 條目。  
> 本檔與 I2V / T2V 研究卡同格式，聚焦參數名、預設值、價格與站內落差。

## #1 Topaz Video Upscale (`fal-ai/topaz/upscale/video`)

| 欄位 | 內容 |
|------|------|
| **官方 Endpoint** | `fal-ai/topaz/upscale/video` |
| **Category** | video-to-video |
| **站內 id / verified** | `fal-ai/topaz/upscale/video` / true |
| **Needs** | video |
| **站內 points / cost** | 7 點 / `$0.01–0.08/秒(依解析度);按秒計費,點數為 6 秒基準` |
| **官方 Required** | `video_url` |
| **官方 Optional** | `model` (ModelEnum, default `"Proteus"`)<br>`upscale_factor` (float 1–4, default 2)<br>`target_fps` (int 16–60，設了才啟用插幀)<br>`H264_output` (bool, default false → 輸出 H265) |
| **model 選項** | Proteus（通用最佳）／Artemis HQ·MQ·LQ（去噪+銳化）／Nyx·Nyx Fast·Nyx XL·Nyx HF（專職去噪）／Gaia HQ·CG·2（渲染/動畫）／Starlight Precise 1/2/2.5·HQ·Mini·Sharp·Fast 1/2（生成式擴散） |
| **站內 input()** | `(_p, _f, s) => ({ video_url: s })` |
| **落差** | **P1**：完全未暴露 `model` / `upscale_factor` / `target_fps`。目前永遠吃 Proteus + 預設 2x。建議至少固定 `model: "Proteus", upscale_factor: 2`，或產品決策暴露進階選項。 |
| **架構筆記** | Topaz 自家非擴散模型家族；插幀可選 Apollo 系。業界標準升頻，低清舊素材救星。 |
| **建議** | 保持 verified:true；文件標「預設 Proteus 2x」；後續可加 UI 選擇 model。 |

## #2 Sync Lipsync v2 Pro (`fal-ai/sync-lipsync/v2/pro`)

| 欄位 | 內容 |
|------|------|
| **官方 Endpoint** | `fal-ai/sync-lipsync/v2/pro` |
| **Category** | video-to-video |
| **站內 id / verified** | `fal-ai/sync-lipsync/v2/pro` / true |
| **Needs** | video |
| **站內 points / cost** | 155 點 / `$5/分;按影片長度計費,點數以 1 分鐘短片估,較長影片實際費用更高` |
| **官方 Required** | `video_url` + `audio_url` |
| **官方 Optional** | `sync_mode` (SyncModeEnum, default `"cut_off"`)<br>選項：`cut_off` / `loop` / `bounce` / `silence` / `remap` |
| **站內 input()** | `(p, _f, s) => ({ video_url: s, audio_url: p.trim() })` |
| **落差** | **P1**：用 prompt 欄塞 `audio_url`，功能可行但 UX 差（使用者需把音訊網址貼在提示詞）。`sync_mode` 未暴露，永遠 cut_off。sourceHint 已提示「提示詞欄貼音訊網址」，但仍易誤解。 |
| **價格備註** | Pro $5/分；標準 v2 約 $3/分。長片費用遠高於扁平估點。 |
| **架構筆記** | Sync Labs 最新一代對嘴，保留牙齒與臉部細節；支援多種 duration mismatch 處理模式。 |
| **建議** | 短期維持現狀 + 強化 sourceHint；中期產品決策獨立 audio source 欄位或明確 UI 說明。 |

## #3 RIFE (`fal-ai/rife/video`)

| 欄位 | 內容 |
|------|------|
| **官方 Endpoint** | `fal-ai/rife/video` |
| **Category** | video-to-video |
| **站內 id / verified** | `fal-ai/rife/video` / true（recommended） |
| **Needs** | video |
| **站內 points / cost** | 2 點 / `$0.0013/運算秒(極低);點數為 6 秒基準` |
| **官方 Required** | `video_url` |
| **官方 Optional** | `num_frames` (int 1–4, default 1)<br>`use_scene_detection` (bool, default false)<br>`use_calculated_fps` (bool, default true)<br>`fps` (int 1–60, 僅當 use_calculated_fps=false)<br>`loop` (bool, default false) |
| **站內 input()** | `(_p, _f, s) => ({ video_url: s })` |
| **落差** | **P2**：基本正確。可選加 `num_frames: 1` 明確化；進階參數（scene detection / fps）可維持預設。 |
| **架構筆記** | 開源即時補幀（RIFE），24→48/60fps 或慢動作。站內 recommended，最適合 AI 生成影片卡頓修飾與老影片流暢感重建。 |
| **建議** | 維持現狀；文件標「預設補 1 幀」。 |
