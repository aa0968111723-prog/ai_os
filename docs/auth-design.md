# 登入・團隊・組別系統設計（任務卡 #002 研究產出）

> 2026-07-12 · 依 Bruce 指示「登入要細膩，分團隊和組別」研究定案

## 1. 研究：業界怎麼做兩層組織

| 產品 | 上層 | 下層 | 借鏡 |
|---|---|---|---|
| Slack | Workspace | Channel | 邀請制進 workspace、channel 內容隔離 |
| GitHub | Organization | Team | org admin 管全部、team 內自治 |
| Notion | Workspace | Teamspace | 成員可屬多個 teamspace、各有角色 |
| Frame.io | Account | Team/Project | 審批權跟角色走、不跟人走 |

**結論**：兩層階層＋邀請制＋「角色是關係不是屬性」（同一人可在 A 組是組長、B 組是組員）是業界共識，直接採用。

## 2. 組織模型（對應基金會現實）

```
超級管理員（Bruce）─ 跨團隊看全部
└─ 團隊 Team（例：總會小編團隊、北區工作組）
   ├─ 團隊管理 team_admin（=總管理：管本團隊所有組、成本總控、邀請）
   └─ 組別 Group（例：剪輯組、動畫組、短影音組）
      ├─ 組長 leader（審批、管本組）
      └─ 組員 member（本組內創作，只見本組）
```

## 3. 資料表（6 張認證表 + 內容表全部掛 group_id）

- `users`：email 唯一、`password_hash`（bcrypt）、is_super_admin、status
- `teams` / `groups`（group 屬於 team）
- `team_members`（user×team：admin/member）
- `group_members`（user×group：leader/member）→ **角色是關係**，一人可跨多組
- `invites`：email＋目標團隊/組＋角色＋一次性 token＋72h 過期 → **邀請連結用 LINE 傳即可**（不用寄信服務，貼合團隊日常）
- `sessions`：隨機 token（DB 存 SHA-256 雜湊）、30 天過期、httpOnly cookie

## 4. 關鍵設計決策

| 決策 | 選擇 | 理由 |
|---|---|---|
| 憑證 | **Session cookie**（httpOnly）非 JWT | 5–20 人內部工具：可即時撤銷、無 token 洩漏面、實作簡單 |
| 密碼 | bcrypt（cost 10） | 業界標準、純 JS 版免原生編譯（Alpine 容器友善） |
| 註冊 | **無公開註冊**，只有邀請連結 | 內部工具鐵律 |
| 權限查驗 | **每次請求重查成員表** | 成員被移出→下一個請求立即失效，無殘留權限 |
| 隔離 | 應用層雙檢查（procedure 守衛＋查詢一律帶 group 過濾） | RLS 留待日後上 Supabase/pg 政策時補第二層 |
| 登入防爆破 | 同帳號 15 分鐘 5 次上限 | 夠用且零依賴 |

## 5. 權限矩陣

| 動作 | 組員 | 組長 | 團隊管理 | 開發者 |
|---|---|---|---|---|
| 看/建本組專案、生成、留言 | ✓ | ✓ | ✓（本團隊全組） | ✓ |
| 審批（通過/退回） | ✗ | ✓ 本組 | ✓ | ✓ |
| 邀請成員、建組 | ✗ | ✗ | ✓ 本團隊 | ✓ |
| 建團隊、跨團隊總覽 | ✗ | ✗ | ✗ | ✓ |
| 看別組內容 | ✗ | ✗ | 本團隊內 ✓ | ✓ |

## 6. 邊界情況（先想好）

- **成員被移出組**：每請求重查 → 立即失效 ✓
- **邀請連結外流**：一次性＋72 小時過期＋接受即作廢
- **最後一位管理員**：禁止移除/降級自己（保底檢查）
- **同 email 再邀請**：附掛既有帳號、不重複建帳號
- **多組成員**：前端「組切換」膠囊，activeGroup 記在本機
- **開發便利**：`AUTH_MODE=dev` 可跳過登入（自動以種子開發者身分），測功能不卡登入
