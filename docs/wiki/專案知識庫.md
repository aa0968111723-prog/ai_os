# 專案知識庫

## 是什麼？

專案內的**長文素材庫**（DB 存全文）：開示稿、見證、腳本、筆記。  
**AI 導演／助手／代理**會自動讀；**圖／影生成不直接灌整庫**。

| 類型 | 用途 |
|------|------|
| transcript | 開示／逐字稿 |
| testimony | 見證 |
| script | 腳本 |
| note | 其他筆記 |

單筆約 4 萬字上限；軟刪進回收桶後**不再注入 AI**。

---

## 注入怎麼優化（現行）

核心：`buildKnowledgeContext` → `shared/knowledgeInject.ts` 的 `assembleKnowledgeContext`。

### 優先序

1. **preferIds**（代理／呼叫端指定）  
2. **釘選 `pinned`**（使用者在知識庫列按「釘選」）  
3. **mode** 決定其餘  
4. 同層再依**建立時間新→舊**

### 模式 `mode`

| 模式 | 用途 |
|------|------|
| `balanced` | 預設；腳本／開示配額較高（腳本 40%、開示 30%、見證 15%、筆記 15%） |
| `script_first` | 腳本先塞，剩餘再給其他 |
| `script_only` | 拆分鏡：只腳本、**不含**角色／場景卡；預算可放寬至 12k |
| `flat` | 釘選後純時間序（近似舊行為） |

### 卡片

知識長文**之前**先注入角色定裝＋場景設定精簡段（字數算進預算）。`script_only` 關閉卡片。

### 截斷透明

- 拆分鏡回報是否截斷  
- UI「預覽 AI 會讀什麼」：`knowledge.injectPreview`（不呼叫 LLM）

---

## 怎麼用

1. 重要腳本／開示按 **釘選**  
2. 開 **預覽 AI 會讀什麼** 確認誰 full／partial／未納入  
3. 庫很大時：釘主腳本、刪或回收雜訊筆記  
4. 拆分鏡：盡量用「腳本」類型；未貼文時系統走 `script_only`
