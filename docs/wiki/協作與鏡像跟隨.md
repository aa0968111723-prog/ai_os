# 協作與鏡像跟隨

## 功能

同一專案可多人同時在線，**組層級**也能互相看到誰在場：

- **Presence**：誰在這個專案／這個組  
- **游標／編輯區**：對方大致在看哪、編哪  
- **鏡像跟隨**：跟隨端捲動對齊對方焦點（**不是**螢幕串流）

### 兩種房間

| 房間 | WebSocket 參數 | 用途 |
|------|----------------|------|
| 專案房 `p:${projectId}` | `/ws?projectId=<uuid>` | 專案頁高精度錨點、游標、zone 編輯指示、鏡像跟隨 |
| 組房 `g:${groupId}` | `/ws?groupId=<uuid>` | Launchpad／排程筆記／資料庫：全組 presence + 游標，讓彼此找得到誰在線 |

專案房與組房互不干擾；同一使用者可同時連兩邊（例如一個分頁在專案、一個在作業台）。

前端：`useCollab(id, enabled, kind)`，`kind` 預設 `"project"`；Launchpad、排程筆記（`/planner`）、資料庫（`/databases`）傳 `"group"`。

## 精準度（實機雙帳測過）

| 層級 | 表現 |
|------|------|
| 誰在場 | 高 |
| 在哪一區／哪張卡 | 高（唯一錨點 `#sec-*`、`#scene-*` 等） |
| 螢幕高度鎖定 | 中高（協定含 `vy`／`vx`） |
| 像素級 1:1 | 不做；長捲時可能有約數十～百 px 殘差 |

高準度機制摘要：錨點 + 卡內比例 + 視窗比例鎖定 + 巢狀捲動 + 展開 `<details>`（含手機收合）。組房以 presence／粗游標為主，不做專案級鏡像跟隨。

## 使用注意

- 點「鏡像跟隨」進入；再點已跟隨的名字會 **取消**（toggle）  
- 雙方版面差很大（手機收合 vs 桌機）時只能粗定位  
- 前端：`client/src/realtime.tsx`；後端轉發：`server/services/realtime.ts`  
- 實機腳本（需帳密環境變數）：`scripts/e2e-ui/verify-collab-mirror.mjs`

## 與世界觀的關係

協作對齊的是**同一專案狀態**；世界觀的一句話故事則讓 **AI 與交付文件**也對齊同一敘事。兩者互補：人跟得上畫面，模型跟得上故事。

## 2026-08 更新：Presenter 場次與語意跟隨

本頁描述的**像素級鏡像跟隨保留不變**，並新增一種與它互補的跟隨方式。

### 兩者的差別

| | 鏡像跟隨（既有） | Presenter 語意跟隨（新增） |
| --- | --- | --- |
| 同步什麼 | 像素：捲動量、游標比例、錨點矩形 | 內容物件：② 分鏡 → 第三場 → Shot 08 → Visual |
| 誰發起 | 跟隨者自己挑一個人跟 | 主講者按「帶大家看」，其他人**收到邀請卡**才加入 |
| 跨裝置 | 版面差很大時只能粗定位 | 手機與桌機都能到同一格 |
| 適用 | 同尺寸桌機、要看細部 | 帶全組看同一個東西 |

目標是 **semantic-perfect collaboration**，不是 pixel-perfect screen sharing。
兩者互補：viewState 先把人帶到正確的物件，鏡像再對齊細部。

### 三條不可違反的規則

1. **絕不未經同意切走畫面。** `present` 訊息在伺服器端只做廣播；
   收到它的客戶端只會長出一張「Bruce 正在帶大家看 [加入] [不用了]」的卡。
2. **跟隨者自己一動就暫停**，顯示「已暫停跟隨（你自己捲動了）[回到 Bruce]」。
   絕不硬拉回去。
3. **主講者離線就明說是誰離線**（「Bruce 暫時離線」），
   **絕不自動改跟另一個在線的人**。

### 為什麼暫停守衛不用 `isTrusted`

程式化捲動（`scrollTo` / `scrollIntoView`，也就是跟隨自己造成的那些）發出的 `scroll`
事件 `isTrusted` **同樣是 true**——它來自瀏覽器引擎，不是腳本合成的。
拿它分辨「人的手」與「我們自己捲的」根本分不出來。

改成從**監聽清單**下手：只聽 `wheel` / `touchmove` / `pointerdown` / `keydown`
（只會由真實輸入裝置產生），**刻意不聽 `scroll`**。

### 多分頁

同一個人可能 Tab A 開故事、Tab B 開分鏡。presence 以 userId 去重是對的
（畫面上他只是一個人），但跟隨不能——只鎖 userId 會讓跟隨者在兩個分頁的位置之間
每秒來回彈跳。每條連線有 `connId`，跟隨鎖定 `userId + connId`。

### 實機腳本

`scripts/e2e-ui/verify-presenter.mjs`（兩個真帳號、兩個 browser context、真 WebSocket）
——涵蓋邀請／不接受不被拉走／加入／跟隨／暫停／回到／主講者離線，
以及手機 390×844 的 touch target ≥ 44px。目前 12/12 通過。

> 這一支抓到三個單元測試全綠但實機會壞的缺陷，其中一個是訊息競態：
> 斷線時 `present` 與 `presence` 是兩則獨立訊息、抵達順序不保證，
> 靠在場名單去推「他是自己結束還是斷線」必然會讀到還沒更新的名單。
> 修法是讓訊息自己帶著語意（`reason` 欄）。

## 2026-08 更新（二）：Story 共編（`/ws-doc`）

故事編輯器現在支援 Google Docs 式共編——**只有 Story**，其他欄位仍走
`rev` 樂觀鎖＋衝突卡（那裡的併發密度用不到 CRDT）。

| | 說明 |
| --- | --- |
| 傳輸 | 獨立 `/ws-doc?doc=story:{projectId}`，**不塞進既有 `/ws`**；沿用同一個 session cookie 與專案 ACL（`authorizeRealtimeConn`），沒有第二套認證 |
| CRDT | Yjs（`Y.Text`）；client 差量進 doc，伺服器 relay 並持久化 |
| 持久化 | `collab_documents` 存完整快照（snapshot 即 compaction）；1.5s 防抖，最後一人離開時 flush |
| materialize | 每次落盤寫回 `stories.content`——parser／AI／export／search 照常工作；走 `applyWithRevision` 所以舊 autosave client 撞上會看到衝突卡，不會互相覆蓋 |
| caret | awareness 帶 userId／名字／顏色（伺服器蓋章，與 `/ws` presence 同一個 8 色雜湊）；textarea 上用鏡像 div 量測畫出夥伴的名牌與游標 |
| 降級 | 連不上／斷線＝自動退回既有 autosave 路徑。共編是升級，不是把唯一的儲存路徑換掉 |

實機腳本：`scripts/e2e-ui/verify-story-coedit.mjs`（兩帳號同時輸入、收斂、
caret 名牌、重新整理後持久）。目前 8/8 通過。

> 這一支也抓到一個單元測試全綠但實機會壞的缺陷：React StrictMode 雙掛載開了
> 兩條 socket，第一條被中止的 socket 其 `onclose` **非同步**遲到，把共用的
> `wsRef` 清掉——畫面顯示「共編中」、字卻一個都送不出去，且舊 autosave 也被
> `active=true` 擋住。修法：事件處理器掛在各自連線上，遲到的 `onclose` 先驗
> 「我還是目前那條連線嗎」才准清狀態。
