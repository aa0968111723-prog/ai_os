## 情境對應手冊(scenario playbook)

### 每日金句卡・繁體中文書法/直排字(最高頻日常)

- **推薦**:Qwen Image 2.0(量產,$0.035/張≈1點)→ 成品級升 Qwen Image 2.0 Pro 或 GPT Image 2(逐字零錯字)
- **用法**:直接打中文描述+要放的字句即可,免調參。中文字渲染是多數模型的死穴,這條情境務必鎖在 Qwen/Seedream/GPT Image 梯隊,絕不要用 FLUX/Imagen/Ideogram 寫中文。放大字卡時只用忠實型放大器(Thera),生成式放大會把字改成亂碼。
- **替代**:Seedream 4.5(多文字區塊版面);草稿試構圖用 FLUX.1 schnell/Sana(每張不到 0.2 點)

### 含中文標題的活動海報/募款文宣(多主體+多文字區塊)

- **推薦**:Seedream 4.5(或 5.0 Pro)出主視覺;向量 logo/字標另走 Recraft V3(SVG,可印刷,但不寫中文字)
- **用法**:Seedream 管中文版面、Recraft 管圖形識別——兩者分工而非二選一。要印大圖時接 Topaz Image 或 SeedVR 放大;含中文字的部分鎖忠實型放大。
- **替代**:GPT Image 2(中英日並存、逐字精準,單張最貴可到 13 點,留給零錯字的對外正式物)

### 莊嚴人物寫真/師父・志工紀實感主視覺

- **推薦**:Imagen 4 Ultra 或 FLUX1.1 [pro] ultra($0.06≈2點);經濟檔 Imagen 4 Fast($0.02)
- **用法**:膚質光影最乾淨的兩檔。打字即出、免參數。注意:這是「生成不存在的畫面」,涉及師父本人形象時改走真實照片+編輯/打光路線(見下),不要憑空生成師父。
- **替代**:FLUX.2 [pro] / Nano Banana 2(指令理解更強,適合敘事定調圖)

### 見證故事・主角跨十多個分鏡同一張臉(人物一致敘事短片,核心情境)

- **推薦**:三步鏈:(1)Ideogram Character(單張參考照→全片同人,turbo 約 3 點/張)或 Nano Banana 2 Edit 定角色分鏡圖 →(2)Kling 2.5 Turbo Pro i2v 或 Hailuo 2.3 Pro i2v 把分鏡動起來 →(3)MMAudio V2 補環境音+auto-subtitle 上字幕
- **用法**:關鍵觀念:純文生影片做不到跨鏡同臉,一定要「先出圖鎖角色、再圖生影片」。長期反覆用的固定角色(吉祥物/虛擬主持人)才升級訓練 LoRA(一次 65–200 點攤提);一次性故事用 Ideogram Character 更划算。

### 師父開示錄音→逐字稿→可剪輯大綱(內容 pipeline 最上游)

## 跨類抉擇心法

跨類抉擇可濃縮成五條心法。【一、什麼時候該花大錢用旗艦】只有三種場合值得上旗艦:(1)對外門面——正式形象片關鍵鏡頭(Veo 3.1 含音、Kling 2.6 Pro)、募款文宣主視覺(Imagen 4 Ultra、Nano Banana Pro)、零錯字對外字卡(GPT Image 2);(2)不可重來的珍貴資產——師父歷史影像修復(Topaz)、近景對嘴(Sync Pro/sync-3);(3)版權必須最保險——對外發布配樂(ElevenLabs Music)、商用合規去背(Bria RMBG 2.0)。其餘 90% 的日常產出,經濟檔品質已足:圖用 Qwen/FLUX.1 dev/Imagen Fast、影用 Wan 2.2/Seedance Lite、音用 MiniMax/Qwen TTS——差價 5–20 倍,肉眼差距遠小於價差。【二、影片成本控制心法】影片是全站最貴類別且多按秒計費,三招控管:先用 LTX/Wan/Fast 檔大量試方向(1–5 點/支),選中的鏡頭才上旗艦重生成;「要不要聲音」做成明確開關(Veo 含音是無音兩倍價),便宜路線是無聲 Wan+MMAudio 補音(1/10 價格逼近有聲);要長片就分鏡拼接,不要單支拉長秒數。【三、中文內容的模型選擇】一條鐵律:畫面裡要出現中文字→只能用 Qwen/Seedream/GPT Image 梯隊(圖)與忠實型放大器(Thera),影片模型一律寫不出正確中文字,字卡另做再疊;中文「語音」→MiniMax/Qwen TTS 原生梯隊;中文「提示理解」→Kling/Wan/Hailuo/Seedance 華語系較懂情境詞;中文「文案語域」→Claude(分寸)與 Gemini Flash(日常);中文 OCR→GOT-OCR 2.0,遠離 Florence-2。【四、生成 vs 加工的抉擇】涉及師父與真實見證者,優先走「真實素材加工」路線(去背、換背景、打光、修復、放大——像素不重繪,莊重性有保證);「憑空生成」留給不存在的畫面(空鏡、插畫、示意場景)。忠實 vs 生成這條軸貫穿放大、修復、編輯三類:要可信選忠實型,要起死回生才選生成型並人工檢查。【五、角色一致的正確路徑】一次性故事→Ideogram Character/Nano Banana 參考圖;跨影片鏡頭→先出圖再 i2v,或 Vidu Q1/Kling O1 reference;長期反覆用的固定角色/風格/聲線→才值得訓練 LoRA/Voice Clone(一次投資全員共用)。

## 四鏡頭總評

### 創作者價值

fal 生態對弘法創作者的總價值是「把整條影音產線的每個工序都降到打字/丟檔案的門檻」:最痛的中文字卡亂碼有解(Qwen/Seedream/GPT Image)、最難的角色跨鏡一致有解(Ideogram Character+i2v+reference-to-video)、最貴的配音配樂變成 1 點級日常(MiniMax/Qwen TTS、Lyria/MiniMax Music)、最枯燥的逐字稿自動化(Scribe v2)、最感人的老照片復活成本不到 1 點(修臉→上色→放大→微動)。更重要的是它同時支撐兩條路線:「憑空生成」補足缺畫面缺攝影的短板,「真實素材加工」(去背/修復/打光/放大/對嘴)讓數十年累積的真實影音資產重新可用——後者對重視真實見證的佛教基金會,價值甚至高於前者。創作者不必懂任何模型,只要會描述「我要做什麼」。

### teamPractical

實用性分三層。天天用得上的剛需:中文字卡與海報(文生圖)、口語編輯/去背/清雜物/換背景(圖生圖)、空鏡 B-roll 與分鏡動起來(t2v/i2v)、中文旁白(TTS)、逐字稿(STT)、墊底配樂音效(music)、字幕燒錄與補音(後製工具)、老照片與舊影帶修復(restoration)——這八塊就是弘法影音團隊的日常,fal 全部有成熟端點。高價值但低頻:LoRA 訓練(管理員代訓 3–5 顆全員共用)、多語對嘴、虛擬主持人。華而不實/不建議收:3D 生成(輸出網格檔,最後一哩缺口,非工程團隊用不上)、換臉(倫理紅線)、虛擬試穿、ControlNet 裸參數全家桶、AuraFlow 等研究型開源檔、MusicGen(非商用授權)。現有 70 檔目錄的最大實用缺口:image-to-video 整類缺席(分鏡圖無法在系統內成片)、影像放大修復整類空白、LoRA 推論端點斷鏈、中文字最強的 Qwen 系未收。

### teamConvenient

方便性的關鍵洞察:fal 模型的上手難度呈三級分布——一鍵級(打字/丟圖即得:Nano Banana、Qwen、去背、修復、放大、TTS 主力)、中等級(要兩個輸入:對嘴、首尾影格、參考圖組)、工程級(遮罩、ControlNet、ffmpeg JSON、LoRA 訓練)。產品要讓創作者零研究,就是把這個分級消化掉:一鍵級做成明確的功能卡(「去背」「清雜物」「修老照片」「做金句卡」),中等級用引導式 UI(先上傳影片、再貼音訊),工程級一律包進預設工作流後端、絕不暴露參數。挑選器呈現「情境」而非「模型」——創作者選「我要做見證故事短片」,系統自動路由到對的模型鏈與預設參數;需調參的一律包成「保守/標準/積極」三檔語意化預設,含中文字時自動鎖保守。做到這件事,fal 六百個模型對創作者就只是十幾張情境卡。

### techFeasible

技術上高度可行:九成端點是「URL 進、URL 出」的單純型態(prompt→圖、image_url→圖/影、text→音、video_url→影),與現有 models.ts 的 needs/kind 架構相容,串接難度低;成本量級全部在點數制承受範圍(圖 0.1–13 點、影 1–93 點、音 1 點級)。主要串接風險有五:(1)fal.ai 對自動抓取一律 403,所有端點 slug 與價格靠搜尋摘要+第三方交叉驗證,少數新版(Seedance 2.0、Kling 3.0、Nano Banana Pro、Lyria 3)slug 未定——務必沿用 verified=false+首跑失敗自動退點機制,勿寫死;(2)計費模型不一致:按張/按 MP/按秒/按分/按運算秒/按 token/按步數並存,固定扣點對長片、長逐字稿、含音影片會低估,需分別換算並在 UI 標註;(3)已發現的目錄錯誤要修:sync-lipsync v2 pro 實為 $5/分、whisper 是按運算秒非音訊秒、bria 影片端點命名空間已遷移、flux-2/pro 與 flux-2-pro 斜線寫法待確認、amt-interpolation 端點存疑應換 RIFE;(4)schema 需三項擴充:新增 image-to-video 類別、多來源輸入欄位(對嘴/首尾影格/姿勢轉移都要兩個輸入)、LoRA 資產型別(存 safetensors URL+觸發詞並轉存自家儲存);(5)fal 未上架的不要虛列:CosyVoice/Fish Speech/XTTS、SenseVoice/FunASR、Meshy、TripoSG 查無 fal 端點,寫入會白扣點。

## 產品建議(如何把研究放進系統)

1. 【結構性缺口第一優先】新增 image-to-video 這個 ModelCategory(型別+CATEGORIES+挑選器):現有 70 檔竟無一 i2v 端點,創作者做好的分鏡圖無法在系統內成片。首批收 Wan 2.2 A14B i2v(recommended 經濟主力)、Kling 2.5 Turbo Pro i2v、Hailuo 2.3 Pro i2v(人物)、LTX(1–2 點預覽)、Kling O1+Wan-FLF2V(首尾影格,UI 加「結束影格」欄位)。
2. 【第二優先】補 LoRA 推論端點修復斷鏈:目錄有 7 個訓練器卻沒有任何掛 LoRA 的生成端點,訓練成果無處可用。補 flux-lora、flux-2/lora、qwen-image(loras)、wan/v2.2-a14b/*/lora;並把訓練輸出改為「LoRA 資產」型別(safetensors URL+觸發詞,自動轉存自家儲存),UI 鎖步數上限防超支。
3. 【第三優先】補中文命脈模型:Qwen Image 2.0/Pro(中文字渲染 SOTA,設為「中文字卡」情境預設)、Qwen Image Edit Plus(改字不跑版)、Qwen 3 TTS(中文旁白經濟主力)、GPT Image 2(零錯字對外物料)、qwen-image-trainer(自家風格+中文兼得)。這是本團隊每天在做卻目錄最缺的一塊。
4. 【第四優先】開「放大與修復」功能區(目前整類空白):photo-restoration(一鍵修老照,recommended)、DDColor(上色)、CodeFormer(修臉)、Thera(中文字忠實放大)、AuraSR(經濟忠實)、Clarity(旗艦創意)、Topaz Image(印刷級)、SeedVR2 影像/影片(批量省錢檔)。
5. 挑選器改為「情境優先」:創作者看到的是情境卡(做金句卡/見證短片/修老照片/配旁白/找配樂…),不是模型清單。每個情境預綁推薦模型鏈+預設參數+prompt 範本,模型名只在進階視圖顯示。本研究的 scenarioPlaybook 可直接做成產品內的「情境手冊」。
6. 一鍵功能卡取代萬能編輯框:去背、清雜物、換背景、擴圖改比例、重新打光、修老照片、補環境音、燒字幕——這些專一任務型端點結果比通用大模型更可預期,做成一顆顆清楚按鈕最符合「不用研究模型」的目標。
7. 預設工作流(多步鏈)產品化:至少四條——「見證故事短片」(定角色圖→i2v→補音→字幕)、「老照片復活」(修臉→上色→放大→微動)、「照片合成」(去背→Nano Banana 合成)、「完整短片經濟版」(Wan→MMAudio→auto-subtitle→ffmpeg 合成)。ffmpeg/ControlNet/遮罩類一律只以工作流後端形式存在,不單獨曝露。
8. 點數透明三件套:(1)按秒/分/MP/token 計費的模型,在卡片上標「以 N 秒為基準,長片另計」;(2)「要不要聲音」做成明確開關並顯示點數差(Veo 含音兩倍價);(3)長逐字稿/長片執行前顯示預估點數確認。
9. 修正已發現的目錄錯誤:sync-lipsync/v2/pro 標價改 $5/分(現標 $0.7–2/分嚴重低估)、fal-ai/whisper 計費單位改「運算秒」、Scribe 價格重查($0.008/分)、bria 影片去背命名空間改 bria/*且單價下修一個量級、amt-interpolation 換成已驗證的 fal-ai/rife/video、flux-2/pro vs flux-2-pro 斜線寫法首跑確認。
10. 上線策略沿用 verified=false+首跑失敗自動退點:所有本次新增端點(尤其 2026 新版 slug 未定者:Seedance 2.0、Kling 3.0/O3、Nano Banana Pro、Lyria 3、Qwen Max)先標未驗證,首跑實測扣點校準,勿寫死價格;fal 官網 403 使所有價格皆屬「執行前以 fal 計價頁為準」。
11. 系統層內建「簡轉繁(OpenCC)+佛學術語詞庫」後處理:任一 STT/LLM 出稿自動變繁體正稿;術語表(法名、經名、專有名詞)做成團隊共用欄位,同時餵給 Scribe keyterm 與 LLM 提示。
12. 倫理規範寫進產品而非公約:換臉/角色替換/偽造發言一律禁用;對嘴限「本人影像+本人授權配音」;真人(尤其師父)肖像與聲音克隆需書面授權確認步驟;Live Portrait/往生者影像需家屬同意提示;MusicGen 非商用授權直接不收;去浮水印限自有素材並在 UI 明示。
13. 參數語意化:Clarity 的 creativity、CodeFormer 的 fidelity、FLUX strength 等一律包成「保守(最忠於原圖)/標準/積極」三檔;偵測到來源圖含中文字時自動鎖保守檔並提示,防止生成式放大把字改成亂碼。
14. 3D 生成類延後、低優先:輸出是 GLB/OBJ 網格非影片,非工程創作者用不上(最後一哩缺口),且需擴充 OutputKind schema。若開實驗入口最多收 Trellis+Hunyuan3D 2.1+一支旗艦,並明確警示「輸出為模型檔,需 3D 後製能力」。
15. schema 擴充排程:多來源輸入(needs/sourceUrl 陣列化)是收錄對嘴、首尾影格、姿勢轉移、參考圖組(Kling O1 七參考)的前置工程,優先於再擴模型數;素材庫與預覽需支援透明 PNG(棋盤格底)與 webm alpha 播放。
